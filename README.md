# Ceru Music 插件系统 v2 设计方案

> 状态：架构设计提案，可作为拆分开发任务、定义 SDK 和评审安全边界的依据。  
> 日期：2026-09-18。  
> 范围：面向当前 Electron 桌面软件，独立于仓库实际代码，只描述目标架构与协议；未来其他客户端仅预留适配边界，不纳入本次实现要求。本文中的单文件格式、API、CLI、权限名均为拟议设计，不代表已经实现。  
> 核心方向：**Electron Host + 可见/不可见模块 + 寄生插件关系 + 单 JS 发行与动态发放 + 可撤销授权 + 无需上传插件的歌曲分享。**

阅读路线：总体设计见第 1–5 节；单文件格式见第 6 节；协议、界面与权限见第 7–12 节；**寄生插件见第 13 节、动态生成见第 16 节、歌曲分享见第 17 节**；Electron 范围见第 18 节；开发分期和验收见第 21–23 节。

## 1. 建议先确定的架构结论

Ceru Music 应成为一个具有稳定音乐协议的插件宿主。搜索、音源、音乐库、发现、歌单、排行榜、导入、皮肤和内容页面，都可以由插件提供。官方原有功能也通过相同扩展协议交付。

“万物皆插件”在业务层成立；身份验证、权限裁决、运行隔离、安装校验和应急恢复必须保留在可信内核中。它们可以有内部模块划分，但不能被第三方插件替换或绕过。

建议采用以下默认决策：

| 议题 | 建议 |
| --- | --- |
| 插件组织 | 一个 .js 发行文件可包含后台逻辑、声明式界面、自定义界面和静态资源 |
| 寄生关系 | 原生兼容器插件管理外部格式子插件；Host 只提供通用受控托管机制 |
| 可见与不可见 | 是模块能力，不是互斥的插件类型；同一包可同时具备两者 |
| 扩展机制 | 服务注册、依赖声明、事件、命令、界面插槽、结构化决策钩子 |
| 运行环境 | 不可信代码进入独立受限运行单元，通过异步 RPC 调用 Host |
| 默认界面 | Host 渲染的 UI Schema；高级界面使用独立沙箱 Web Surface |
| 来源模型 | 搜索提供者、内容提供者、播放解析器相互独立，以能力发现代替固定平台枚举 |
| 权限模型 | 静态声明上限、使用时授权、每次调用校验、随时撤销 |
| 默认行为覆盖 | 允许在有归属、有期限的当前操作内提出覆盖请求，由 Host 仲裁 |
| 安装分发 | 最终只分享一个 .js 文件；静态安装预览、内嵌签名、权限差异审查、原子更新与回滚 |
| 开发构建 | npm CLI/脚手架建立多文件工程，构建时合并依赖与资源，输出一个可安装文件 |
| 动态发放 | 核心只构建一次，按用户生成受控配置与发放证明，流式输出一个 JS |
| 歌曲分享 | 插件在客户端导出分享能力，服务端只处理数据与固定分享协议 |
| 当前端范围 | 只实现 Electron；稳定业务协议和系统适配接口便于未来扩展 |

第一版就应完成四个闭环：**纯后台音源插件、可连接账号的 Navidrome 插件、可注入导入按钮的歌单导入插件、可托管 LX 脚本的兼容器插件**。它们共同验证架构，而不是先围绕某一个平台硬编码接口。

## 2. 参考体系的优点、局限与取舍

本节依据公开文档评估设计，未审计三个项目的实际运行代码。“文档未描述”不等于“实现一定没有”。后文的 Ceru 方案是设计建议，不是参考项目已经具备的能力。

### 2.1 DeepSeek Harness / Cordis

Cordis 通过上下文注册功能，以服务依赖决定插件何时可用，并把注册与资源清理纳入生命周期。这适合 Ceru 的后台能力组合：音源、歌词、内容库和导入器可以各自实现服务，再由配置组装。[首个插件](https://deepseek-harness.github.io/deepseek-harness/develop/cordis-tutorial/01-first-plugin)、[生命周期](https://deepseek-harness.github.io/deepseek-harness/develop/cordis-tutorial/02-lifecycle-and-effects)、[服务](https://deepseek-harness.github.io/deepseek-harness/develop/cordis-tutorial/03-services)

它的优势是替换实现和卸载资源有统一规则，组合包与用户配置也有分层。代价是依赖图、热重载和配置覆盖增加了诊断复杂度；缺少依赖时，用户需要看到明确原因。[组合与热重载](https://deepseek-harness.github.io/deepseek-harness/develop/cordis-tutorial/06-composition-and-hmr)、[打包与安装](https://deepseek-harness.github.io/deepseek-harness/develop/basic/publish)

**Ceru 取舍：**吸收上下文、依赖、作用域和自动清理；第三方服务跨隔离边界时使用 RPC 代理。服务的逻辑隔离不能替代安全沙箱，也不能直接把 Node/npm 插件加载方式当作普通用户的安全安装方案。

### 2.4 组合后的方向

| 来源 | 借鉴重点 | Ceru 需要补齐的部分 |
| --- | --- | --- |
| Cordis | 服务、依赖、上下文、自动清理、组合 | 跨进程协议、不可信代码隔离、面向普通用户的诊断 |
| CoCo | 可见/不可见、属性/方法/事件、控件组合 | 模块组合、多账号、后台任务、音乐领域协议 |
| Such | 简洁 SDK、Schema UI、授权与确认 | 资源级权限、完整页面扩展、安装身份与更新链 |

## 3. 产品范围与不可破坏的边界

### 3.1 允许插件定义的内容

- 搜索源的名称、图标、排序建议、搜索类型、筛选项、建议词和结果展现。
- 播放解析来源、音质选项、登录要求、健康状态和限流提示。
- 侧栏导航组、导航项、页面、页面标签和发现区块。
- 歌单、排行榜的分类体系、排序方式、详情页和可选渲染器。
- 导入入口、链接识别、文件解析、平台账号连接和批量导入流程。
- 歌词、封面、评论、播客、电台、个人音乐库、收藏同步等能力。
- 工具栏按钮、上下文菜单、命令面板命令和受控快捷键。
- 主题、布局预设、可复用控件及后续的动作编排。

这些能力不要求存在 tx、kg 等固定平台标识。平台可以作为某个插件自己的内部细节，Host 不据此分支。

### 3.2 Host 始终负责的内容

- 验证插件身份、包完整性、版本兼容性和安装来源。
- 授权、撤权、RPC 鉴权、系统能力代理和资源配额。
- 播放队列一致性、媒体句柄校验、用户停止操作与最终播放仲裁。
- 用户数据的事务、恢复、审计以及可信凭据输入。
- 插件管理、权限中心、紧急停用、恢复默认布局和安全模式。

播放交互界面可以插件化，音频后端也可以采用内部分层服务；第三方插件不能获得“接管全部播放器状态和权限中心”的超级接口。

### 3.3 用户始终能找回软件

即使用户关闭所有业务插件，仍能打开设置和插件管理、查看本地数据状态、恢复官方预设。替换搜索页或导航布局时，保留 Host 的设置入口和应急入口。插件崩溃不能让用户失去撤销该插件的路径。

## 4. 统一概念模型

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| Package | 逻辑安装单元，物理产物是一个 .js 文件 | community.navidrome |
| Adapter Plugin | 负责外部格式和配套体验的原生兼容器插件 | community.lx-compat |
| Guest Plugin | 依附兼容器、由 Host 单独登记与隔离的子插件 | 用户导入的一份 LX 脚本 |
| Module | 包内逻辑或界面模块 | 后台服务、连接表单、音乐库页面 |
| Instance | 包在某个用户配置空间中的运行实例 | 当前配置下启用的 Navidrome |
| Connection | 账号或服务器连接，拥有独立状态和凭据范围 | 家庭服务器、朋友服务器 |
| Provider | 某个实例贡献的能力提供者 | 搜索、目录、播放解析 |
| Contribution | 安装清单声明、运行时实现的扩展项 | 侧栏项、导入按钮、搜索选项 |
| Surface | 用户可见的页面、面板或控件实例 | 连接面板、歌单页 |
| Service | 可被其他模块消费的具名协议实现 | 歌词服务、资源匹配服务 |
| Operation | Host 创建的一次有期限的业务操作 | 一次搜索、播放解析、批量导入 |
| Scope | 自动回收资源和约束权限的作用域 | 插件、连接、页面或操作作用域 |

身份规则：

1. 包 ID 采用命名空间，例如 community.navidrome；正式发布者身份必须由分发信任链验证，不能只相信这个字符串。
2. 包内 ID 使用局部名称，例如 library、connect、search；Host 合成为全局唯一引用。
3. 连接 ID 由 Host 分配，不使用明文用户名、服务器密码或访问令牌拼接。
4. 不同插件里的同名资源互不覆盖。删除后重新建立连接时使用新连接身份，避免误用旧凭据。
5. 禁用插件不自动删除用户歌单；卸载时分别选择保留设置、清除缓存和删除凭据。

**纯不可见插件也可以有搜索选择器条目。**条目是 Host 根据提供者元数据渲染的界面，不要求插件编写可见模块。只有需要自己的表单、页面或交互时，才增加 Surface。

## 5. Host 架构与运行环境

### 5.1 分层结构

~~~mermaid
flowchart TB
  U["用户"]
  S["可信应用外壳：搜索框、导航、播放器、设置、权限弹窗"]
  R["扩展注册表与音乐协议路由"]
  K["可信内核：身份、生命周期、权限、安装、任务与审计"]
  B["能力代理：网络、凭据、媒体、文件、用户数据"]
  L["插件逻辑运行单元：独立受限 JS 环境"]
  V["高级界面运行单元：隔离 Web Surface"]
  J["声明式 UI Schema：由 Host 渲染"]
  D["设备与远端服务"]
  U --> S
  S --> R
  S --> J
  R --> K
  L <-->|"有身份的异步 RPC"| K
  V <-->|"受限界面消息"| K
  J -->|"已声明的动作"| K
  K --> B
  B --> D
~~~

业务插件之间没有共享的 Host 对象引用，不允许直接 import 宿主内部模块。插件编写的 Vue、React 或其他框架代码只能成为沙箱内的界面资源，不能直接挂载进可信应用组件树。

### 5.2 推荐的逻辑运行方案

推荐以 **受限 JS 引擎 + 可终止运行单元 + Host RPC** 为基线，QuickJS 可作为优先验证的候选：

- 每个插件实例独立 JS Runtime；桌面基线进一步使用独立、受 OS 限制的 runner 进程。
- runner 不加载 Node/Electron API，不暴露进程环境、任意文件、套接字或动态本机库。
- 不挂载 QuickJS 的 std/os 等系统模块；模块加载器仅允许已校验单文件内声明的模块入口。第 13 节的 Guest 只额外挂载 Host 已批准的子脚本及指定兼容 bootstrap，不能访问父插件的其他私有模块或资源。
- 对堆、栈、执行时间和任务数量设上限；Host 监控失联并可终止整个 runner。
- 发行文件携带已经完成 JSX/TS 转换的 JavaScript bundle，不接收外部分发的 QuickJS 字节码。编译缓存只能由本机可信流程产生，并绑定代码摘要、引擎版本和 SDK 档位；个性化配置与授权状态独立保存。
- 禁止远程脚本导入和网络响应转代码执行。构建期依赖在开发者端打包，终端用户安装时不运行 npm 生命周期脚本。

QuickJS 提供内存和执行中断接口，但其文档也明确提醒外来字节码的风险。因此它只是执行引擎，安全性仍依赖绑定接口、runner、系统隔离和持续更新。[QuickJS 官方文档](https://bellard.org/quickjs/quickjs.html)

不能把普通子进程等同于沙箱：如果子进程仍拥有用户全部文件权限，引擎被攻破后仍可能影响设备。Windows、macOS、Linux 的系统限制方式需要分别验证；达不到基线的平台应限制第三方代码能力，并明确显示运行等级。

不使用 new Function、Node vm 或普通 Node Worker 作为唯一安全边界。Node 官方明确说明 vm 不是运行不可信代码的安全机制。[Node vm 文档](https://nodejs.org/api/vm.html)

### 5.3 可见模块分成两种

**Schema Surface：默认选择。**插件提交描述和数据，Host 使用自己的组件渲染。适合连接表单、歌单列表、排行榜、工具面板和大多数内容页面。

**Web Surface：高级选择。**插件运行自己的 HTML/CSS/JS 和前端框架，提供复杂视觉、交互或定制页面。必须隔离来源、存储与通信，不能触达 Host DOM。

桌面高级界面采用开启 sandbox、context isolation 且关闭 Node integration 的独立 webContents 或经验证的等效隔离容器；禁止任意导航、新窗口和直接 Electron API。IPC 验证真实发送方，不能相信消息里的 pluginId。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

当前只实现 Electron 中的上述两种界面方式。未来客户端通过独立适配层实现同一协议，不要求现在提供浏览器版或移动端插件执行器。

### 5.4 最小可信计算基

可信范围包括包验证器、runner 启动器、RPC 鉴权、权限存储、能力代理、Schema 解释器与可信外壳。官方插件也尽量走公共协议；必须访问底层设备的官方适配器单独列入可信范围，不能把它的特权授予所有官方业务插件。

### 5.5 生命周期与故障恢复

~~~text
安装状态：
下载 → 校验 → 待用户确认 → 已安装 → 可启用

运行状态：
disabled → pending → starting → active → stopping → stopped
                ↘ blocked       ↘ crashed → quarantined

blocked 原因：
缺少依赖 / 功能所需权限不足 / 平台不支持 / 版本不兼容
~~~

- 安装元数据和权限预览在执行插件代码之前完成。
- 静态贡献可提前显示为“需要配置”；Provider 只有成功激活后才能接收调用。
- activate 阶段将动态注册暂存在事务中，成功后统一发布，失败则全部撤回。
- 每个注册、监听器、任务、视图和请求都有 owner scope；Host 在停用或崩溃时兜底回收。
- 插件自己的清理回调有截止时间。回调卡死不影响 Host 终止运行单元。
- 必需服务消失时停止依赖功能；可选服务消失时降级。诊断页显示完整依赖链与缺失原因。
- 必需依赖形成环时拒绝激活，不能让插件永久无提示地等待。
- 页面关闭只销毁页面作用域；音源逻辑可继续运行。退出账号则撤销该连接的请求、媒体租约和凭据使用权。
- 更新采用旧实例退场、新实例发布的受控切换，注册项带 generation；旧实例的迟到消息一律丢弃。

生命周期借鉴 Cordis 的 effect 思路，但资源所有权记录在 Host 中，不能依赖恶意插件主动执行 disposer。

## 6. 单文件插件格式与 Manifest

### 6.1 开发工程与发行文件分开

最终安装、动态发放和分享给用户的产物统一为 **一个 UTF-8 编码的 .js 文件**。用户直接拖入、选择文件或通过链接安装，不需要 ZIP、解压步骤、外置 Manifest、资源目录或 npm 环境。

文中“插件包”仅表示逻辑安装单元，不再表示压缩容器。可见、不可见和寄生关系都是模块与运行身份的划分，不决定安装文件数量或扩展名。

开发者可以使用 npm CLI/脚手架生成常规多文件工程：

~~~text
my-navidrome-plugin/            开发者工作目录
├── package.json                构建依赖与 npm scripts
├── ceru.plugin.json            开发期 Manifest
├── src/
│   ├── logic.ts                后台模块
│   ├── library.tsx             可选高级界面
│   └── guest-bootstrap.ts      可选兼容层
├── ui/
│   └── connection.json         声明式界面
├── assets/
│   └── navidrome.svg
└── locales/
    ├── zh-CN.json
    └── en-US.json

npm run build
  → dist/navidrome.js           唯一必需的发行文件
~~~

开发期可以使用 TypeScript、JSX/TSX、Vue SFC 或普通 JavaScript；对应框架由脚手架的构建适配器支持。第三方纯 JS 依赖在构建时合并，Host 不运行 npm install，也不读取开发者的 package.json。

### 6.2 单文件的静态结构

建议定义一个版本化的源码文件结构：

1. **文件头**：受限 JSON 注释块，内嵌 Manifest、语法档位和可选签名。
2. **模块表**：每个逻辑、Web Surface、Guest bootstrap 入口独立封装为函数。
3. **资源表**：Schema、多语言、CSS、图标等作为 JSON 或字符串字面量内嵌。

精简示意如下；实际 Manifest 使用第 6.3 节的完整字段。这里 signature 为 null，表示未签名示例。

~~~javascript
/* @ceru-plugin-v2
{
  "formatVersion": 2,
  "syntax": "js",
  "manifest": {
    "manifestVersion": 2,
    "id": "example.hello",
    "name": "问候插件",
    "version": "1.0.0",
    "modules": {
      "logic": { "entry": "logic.main" }
    }
  },
  "signature": null
}
@end-ceru-plugin */
CeruPlugin.define({
  modules: {
    "logic.main": async function (ctx) {
      ctx.log.info('插件已启动')
    }
  },
  resources: {
    "locales.zh-CN": {
      type: "json",
      value: { greeting: "你好" }
    }
  }
})
~~~

CeruPlugin.define 是发行格式的固定注册语法，**不是让 Host 在主进程执行此文件后再得到信息**：

- 安装器以有长度上限的静态解析器读取文件头，不使用 eval、require、import 或执行函数。
- 文件头必须位于约定位置且唯一；拒绝重复 JSON key、多个结束标记及歧义编码。CLI 对注释终止字符做规定转义，防止字符串内容提前结束文件头。
- 验证原文件签名或取得未签名内容的安装批准后，使用受限 AST 解析器检查载荷形状。
- 载荷只允许一个固定注册表达式；模块值必须是函数表达式，资源值必须是限定字面量。拒绝外层执行语句、getter、展开表达式和计算属性。
- 安装器按已声明 ID 提取模块源码和资源，而不是执行模块表。只有具体模块激活时，才在对应的受限运行单元编译与运行。
- Manifest 的入口、资源引用必须与表中记录一一对应。模块或资源不能在安装后通过任意网络代码补齐。
- 构建器把依赖及辅助函数封装在各入口内部，不能依赖发行文件顶层的共享可变对象或跨入口闭包。

这样一个文件可以携带多个模块，但后台、界面和 Guest 仍运行在不同权限与内存边界中。公共资源可由 Host 按只读句柄共享；公共代码分别进入需要它的入口。

约束：

- Manifest 是静态 JSON，禁止通过执行插件求得名称、图标、权限或入口。

- 导航、命令和 Provider 的运行时注册必须落在 Manifest 声明范围内。
- 按账号动态增加条目时，只能从已声明的多连接提供者或动态分组派生，数量受配额约束。
- 页面激活、Provider 激活与命令激活由 Host 去重，避免同一实例启动多次。
- 示例 /rest/ 只是连接协议示意；部署于子路径的服务应解析出实际授权范围，不放宽成任意站点。
- 三个版本轴独立演进：Host API、逻辑运行时、UI Schema；不能只比较应用版本号。

### 6.4 JSX 用于开发，最终统一输出 JavaScript

JSX/TSX、Vue SFC 和 TypeScript 仅属于开发输入。CLI 在构建阶段转换语法、合并运行库与依赖，最终写出标准 JavaScript，文件头的 syntax 固定为 js。例如 esbuild 提供 JSX 转换与依赖合并能力，可作为 CLI 底层构建工具的候选。[esbuild JSX 文档](https://esbuild.github.io/content-types/#jsx)、[构建与合并选项](https://esbuild.github.io/api/#bundle)

可见模块也打入同一个 .js 文件；是否有界面由 Manifest 决定。Host 不在用户安装时编译 JSX/TS，也不安装 React、Vue、Babel 或项目依赖。

Host 仍需对普通 JS 做受限语法分析和引擎编译，并设置文件大小、AST 深度、内存与时间限制。构建时声明目标运行时档位，安装时提前检查兼容性。

签名验证针对发行文件承诺的静态内容；第 16 节的动态发放模式进一步把固定代码与个性化数据分别绑定和校验。编译缓存只复用不可变代码，不复用实例状态或用户授权。

### 6.5 资源内嵌与依赖边界

- JSON UI、语言文本、许可证及必要声明使用静态 JSON/文本资源。
- CSS、SVG、HTML 模板作为字符串资源；图片和必要二进制资源可使用 Base64，由 Host 校验并转成内部资源句柄。
- 资源表不是压缩包，也不是 Base64 包裹的安装归档。v2 发行格式不支持自解压逻辑或“解压后再找入口”。
- 资源 ID 不解释为磁盘路径；Host 用内部 ID 或内容摘要管理缓存，拒绝路径穿越形式的标识和重复条目。
- 高级 Web Surface 的 JS、CSS、模板和字体一并内嵌，由 Host 为该 Surface 构建隔离的虚拟资源空间；不能为方便而在可信页面直接执行嵌入脚本。
- 构建时关闭产生外置文件的代码拆分；动态 import 只能转成文件内已知模块的延迟调用。构建校验拒绝外置 chunk、CSS 文件、必需 sidecar、裸 npm import 和远端模块地址。
- 基础 npm 库打进当前文件；另一个澜音插件仍是独立安装、独立授权的依赖，不把它的程序或权限偷偷合并进来。
- 远端封面、歌曲流、目录数据依然可以按授权动态请求；远端可执行代码、样式和组件不能用这个入口绕过单文件校验。
- 初版建议限制原文件 10 MiB、资源解码总量 32 MiB、元数据头 256 KiB，具体阈值通过原型验证调整。超限时提示精简资源，不静默外置代码。
- Source map 可供开发者本地调试，发行时可选择受限内嵌或不携带；安装器不得自动读取远端 sourceMappingURL。

代码更新按完整 .js 文件进行，暂不引入差分补丁。任意模块变化都形成新的核心发行版本；只有名称或许可证等受控数据变化时，不重新构建代码，使用第 16 节的动态发放流程。

## 7. 音乐领域协议：去掉固定平台假设

### 7.1 搜索源、播放源、内容库分别建模

| 协议 | 责任 | 是否必须提供 |
| --- | --- | --- |
| music.search@1 | 搜索歌曲、专辑、歌单、艺人等 | 否 |
| music.suggest@1 | 查询建议、补全、历史之外的远端建议 | 否 |
| music.catalog@1 | 分类、内容列表、详情、收藏目录 | 否 |
| music.resolve@1 | 将自己的资源引用解析成可播放媒体 | 否 |
| music.match@1 | 为允许跨源匹配的资源寻找本来源版本 | 否 |
| music.lyrics@1 | 歌词及时间轴 | 否 |
| music.comments@1 | 评论与分页 | 否 |
| music.share@1 | 可分享能力、分享计划、接收端资源解析 | 否 |
| playlist.import@1 | 外部输入识别、解析、导入计划 | 否 |
| playlist.sync@1 | 经授权的双向或单向同步 | 否 |
| account.connection@1 | 连接设置、认证状态、退出 | 否 |

插件按实际能力实现，不要求补齐所有方法。Host 只显示可用能力，例如纯播放解析器可以出现在“播放来源偏好”，但不伪装成可以搜索的选项。

同一 Provider 可以实现多个协议，但搜索选项与播放源偏好是两份独立配置：

- **搜索范围**决定把查询发送给谁。
- **播放来源偏好**决定使用哪个已授权来源播放，以及是否允许跨源匹配。

“聚合搜索”“全部已选择来源”“智能匹配”本身也可以是业务插件。聚合必须由用户明确选择参与来源，不能因为安装了插件就向所有服务器广播关键词。

### 7.2 通用数据契约

以下类型是协议草图，最终应由一份机器可验证的 Schema 生成 TS 类型、RPC 校验器和文档。

~~~typescript
interface ResourceRef {
  pluginId: string
  providerId: string
  connectionId?: string
  kind: 'track' | 'album' | 'artist' | 'playlist' | 'chart' | 'station' | string
  id: string
}

interface ContentEntity {
  ref: ResourceRef
  title: string
  subtitle?: string
  artwork?: AssetHandle
  playable?: boolean
  durationMs?: number
  capabilities: string[]
  extensions?: Record<string, JsonValue>
}

interface Page<T> {
  items: T[]
  nextCursor?: string
  snapshotId?: string
  totalEstimate?: number
}

interface SearchRequest {
  query: string
  kinds: string[]
  filters: Record<string, JsonValue>
  cursor?: string
  limit: number
}

interface OperationContext {
  id: string
  deadlineAt: number
  signal: AbortSignal
  connectionId?: string
  userIntent?: UserIntentHandle
}

type ResolveResult =
  | { ok: true; media: MediaLease }
  | { ok: false; error: MusicFault }
~~~

这里的 AssetHandle、MediaLease 是 Host 发放的不透明引用；JsonValue 只允许受限 JSON 数据。AbortSignal 是 SDK 在本地映射出来的对象，在线路上通过取消消息表达，不直接序列化 JS 对象。

关键规则：

- 资源身份包含提供者与连接，不能拿不同平台相同的数字 ID 当作同一首歌。
- 持久资源引用不携带运行时 generation；每次调用时由 Host 解析到当前有效实例并鉴权。
- 分页使用不透明游标。插件内部适配页码或 offset；Host 不猜测接口是从 0 还是从 1 开始。
- 游标绑定查询、筛选、连接和数据快照；条件改变即失效。协议检测重复游标，避免无限加载。
- standard kind 是互操作基础；自定义 kind 使用包命名空间并提供通用标题、封面和可降级列表表示。
- extensions 的 key 必须命名空间化，限制深度和体积；不得塞入凭据、可执行代码或未校验 HTML。
- 艺术作品、封面、头像同样经过资源代理，不能让“返回一个图片 URL”绕过网络权限。
- 播放能力不可由 playable 字段自我授予；Host 还要确认有效的 resolve 协议和当前连接状态。

### 7.3 搜索提供者注册与选择器

每个搜索提供者声明：

- 名称、多语言文案、图标、描述、支持的资源类型。
- 支持的筛选项及值类型，例如年代、流派、收藏状态、音质。
- 是否需要连接账号、是否可离线搜索、是否支持建议词。
- 当前状态：可用、待连接、限流冷却、离线、权限不足。
- 建议展示顺序和默认结果布局。

Host 依据这些声明生成左上角来源选择器。用户可以隐藏、重排、重命名连接别名，并选择默认来源；插件只能更新自己条目的业务状态。

推荐展示：

~~~text
搜索范围
  ● 我的 Navidrome · 家庭服务器
  ○ 开放音乐目录
  ○ 本地音乐
  ○ 聚合搜索 · 已选 2 个来源
  + 管理搜索来源
~~~

插件名称与连接别名可区分展示。同名图标不能掩盖发布者身份；来源详情始终能查看“由哪个插件提供”。

筛选项采用可验证字段定义，Host 提供默认控件；极复杂搜索可注册独立搜索页，但全局搜索仍使用标准协议，或者明确标注该来源只支持独立页。

### 7.4 播放解析与资源匹配

resolve 返回媒体租约，而不是可供任意页面读取的永久裸链接。插件先向媒体代理提交 URL、所需认证引用、有效期和媒体信息，Host 检查后生成租约。

媒体代理负责：

- 在实际连接时再次校验网络范围、凭据范围和权限状态。
- 支持流式读取、Range、取消、超时及媒体链接过期后的受控刷新。
- 对 HLS/DASH 子清单、分片、密钥、重定向逐次检查，不能只检查最外层 URL。
- 默认将认证信息保留在代理侧，避免带 token 的地址进入 UI、日志或导出文件。
- 下载授权与在线播放授权分别检查；“能播放”不自动等于“可以批量下载”。

跨源匹配由可替换的匹配服务实现，但只给候选来源发送经用户允许的必要元数据。匹配结果保留原始引用、目标引用和匹配依据，不能因为同名就永久合并歌曲；版本、时长、艺人差异应可供用户确认。

私有音乐库默认关闭向外部来源发送歌曲元数据的自动匹配。用户可以为具体连接开启，不能从全局“自动换源”推导出对私有数据外发的同意。

## 8. 界面扩展点与渲染自由度

### 8.1 标准扩展点

| 扩展点 | 插件可贡献内容 | Host 规则 |
| --- | --- | --- |
| search.sources | 选项、图标、能力、连接状态 | 从已声明搜索 Provider 派生 |
| search.filters | 筛选字段、枚举、默认值 | 仅作用于对应来源 |
| search.suggestions | 建议词、辅助操作 | 需用户选择来源，限制请求频率 |
| search.results.renderers | 结果卡片、列表或自定义 Surface | 根据资源类型与用户选择匹配 |
| sidebar.groups | 导航分组 | 允许用户排序和隐藏 |
| sidebar.items | 页面入口、状态徽标、子入口 | 不覆盖权限中心与设置入口 |
| routes.pages | 插件独立页面 | 路由命名空间化，不能拦截宿主路由 |
| discovery.sections | 发现页区块、推荐内容 | 各区块独立加载与失败 |
| catalog.categories | 歌单、榜单及其他动态分类 | 返回分类树或分页分类，无固定平台枚举 |
| catalog.layouts | 列表、网格、分组、专属页面布局 | 始终保留可访问的通用降级表示 |
| playlist.detail.tabs | 歌单详情标签页 | 按所属资源和能力决定是否显示 |
| playlist.import.actions | 导入按钮、平台连接与文件导入 | 必须进入可预览、可取消的任务流程 |
| toolbar.actions | 页面工具栏按钮 | 仅接收声明的上下文数据 |
| resource.contextMenu | 歌曲/歌单等资源菜单 | 点击后才传递选中资源 |
| resource.share.actions | 分享模式、要求和来源提示 | 进入 Host 分享预览，只发布经校验的数据 |
| player.panels | 歌词、评论、信息或扩展面板 | 读取当前播放状态需相应授权 |
| settings.pages | 插件配置、账号与高级设置 | 可信授权 UI 由 Host 单独提供 |
| commands | 命令面板命令及快捷键建议 | 用户处理快捷键冲突 |
| themes.tokens | 色彩、密度、圆角、排版、动效偏好 | 不影响可信弹窗的来源标识 |
| widgets | 可复用组件、仪表卡片 | 通过输入/动作/事件契约组合 |

分类和布局应分离：一个排行榜 Provider 可以提供“地区—类型—周期”，另一个提供“服务器—收藏—最近播放”。Host 只理解分类节点、分页和内容协议，不固定两级菜单，也不要求每个来源都叫“排行榜”。

### 8.2 可替换角色与可追加插槽

将扩展点分为两类：

1. **追加型**：侧栏项、详情标签、工具栏动作，可以同时有多个贡献者。
2. **角色型**：默认搜索页、发现首页、某类资源的默认渲染器，由用户选择一个提供者。

安装插件只增加可选项；替换默认搜索页或整块导航需要用户选择。主题包可以建议组合，但不能默默覆盖当前布局。

冲突处理采用稳定顺序：用户排序优先，其次为 Host 定义的分组顺序、限制范围内的建议权重，最后按稳定 ID 排序。禁止插件通过无限大 priority 抢占首位。

贡献 ID 冲突、非法宿主路由、超出声明的插槽注册直接拒绝，并在诊断中说明原因。权限不足时条目可显示“需要授权”，但不能仅靠隐藏按钮实现访问控制。

### 8.3 UI Schema 应覆盖完整的常见页面

Schema v1 建议包含：

- 布局：stack、grid、split、tabs、section、responsive。
- 内容：text、markdown-safe、image、badge、stat、progress、empty-state。
- 输入：text-input、number、select、toggle、date、host-file-picker、host-credential。
- 集合：virtual-list、table、card-grid、tree、paged-collection。
- 音乐组件：track-row、album-card、playlist-card、quality-picker。
- 交互：button、menu、form、drawer-request、dialog-request。
- 数据状态：loading、empty、partial-error、permission-required、offline。

属性绑定采用有限表达式树，例如取字段、比较、与/或、格式化。禁止 eval、任意函数调用、原型链访问、无限递归及通过 HTML/CSS 引入外部代码。Schema 的 URL、富文本、样式和动态数据都按不可信输入处理。

示例：

~~~json
{
  "schemaVersion": "1.0",
  "id": "connection",
  "root": {
    "type": "form",
    "submitAction": "connection.connect",
    "children": [
      {
        "type": "text-input",
        "bind": "serverUrl",
        "label": "服务器地址"
      },
      {
        "type": "host-credential",
        "bind": "account",
        "label": "连接账号",
        "permissionKey": "account"
      },
      {
        "type": "button",
        "label": "连接",
        "action": "connection.connect"
      }
    ]
  }
}
~~~

host-credential 的敏感值留在可信组件和凭据代理中。动作只收到 credentialRef；插件的通用状态对象、页面快照和开发日志不包含密码。真正发出认证请求前，Host 展示实际目标服务器并取得对应授权。

### 8.4 高级 Web Surface

允许插件自带 Vue、React、Canvas 或其他浏览器渲染代码，满足特殊排行榜、沉浸式歌词和完全自定义音乐库页面。

要求：

- 只能操作自己的渲染容器；尺寸、可见性、宿主快捷键和可信状态栏由 Host 管理。
- 代码、样式、字体默认来自已验证单文件中的内嵌模块与资源；动态图片与媒体通过受控资源句柄加载。
- 默认禁止直接网络访问、表单外发、任意导航、弹出窗口和远端 iframe。
- CSP 禁止外部脚本、动态求值与绕过代理的连接；同时用容器网络拦截兜底。
- 在 Electron 中使用独立来源与存储分区，严格限制导航和新窗口；不与可信界面共享一个可被插件脚本访问的文档环境。
- 消息通道与具体窗口/框架实例绑定，验证实际 sender、会话和 generation；不能仅凭 postMessage 数据里的 ID 或不可靠的 origin 字符串。
- 只暴露该 Surface 声明的动作代理，禁止提供任意 IPC、任意 fetch 或任意宿主方法调用器。
- UI 不因与逻辑模块同包就继承全部逻辑权限；逻辑仍需验证动作参数、用户意图和资源范围。

高级界面与原生组件之间统一使用状态快照、带 revision 的局部更新和动作事件。过期 revision、超大更新、过频事件被限流或拒绝。隐藏页面降低更新频率，不能靠动画持续占用后台资源。

### 8.5 图标、主题与无障碍

图标协议支持：

~~~typescript
type IconRef =
  | { kind: 'host'; name: string }
  | { kind: 'asset'; resource: string }
~~~

Host 提供有版本的公开图标目录，例如 search、music-note、library、cloud、server、import、chart。目录中明确许可范围；不把所有内部品牌图标默认当成可自由复用资产。

插件自带 SVG 在安装时清洗，移除脚本、事件、外部引用和危险嵌入，并限制尺寸与复杂度。不存在的 Host 图标使用中性占位图，不能导致安装失败。

所有 Surface 接收主题 token、语言、缩放、输入方式与减少动效偏好。Schema 默认保证键盘操作和读屏标签；高级界面需要通过相应可访问性检查。用户可随时切回通用列表。

### 8.6 通知、弹窗与页面打开 API

提供 ctx.ui.notify、ctx.ui.dialog、ctx.ui.openView 三类入口，分别返回通知句柄、用户选择/关闭结果和页面句柄。参数只接受纯文本或安全组件描述、已声明动作、去重键和作用域，不接受任意宿主 HTML。

普通状态提示优先放在插件页面或消息中心；模态交互必须与当前前台操作相关，受全局队列和频率控制。若在后台调用，Host 可以返回 deferred 并改为待处理卡片。授权弹窗只通过 ctx.permissions.request 产生，不能用普通 dialog 代替真实授权。

播放失败需要暂停换源时，使用第 11 节的原子故障结果，不先单独调用 dialog 再试图停止自动换源。

## 9. 权限与用户授权

### 9.1 四个概念必须分开

1. **声明**：插件可能需要什么能力，是申请上限。
2. **授权**：用户允许哪个插件，对哪些资源，在什么期限内执行什么操作。
3. **租约**：Host 为一次实际调用或操作派生的短期访问权。
4. **执行检查**：每次落到网络、文件、媒体、用户数据等边界时再次验证。

插件声称“我已经获得权限”、界面隐藏了按钮、曾经弹过一次确认，均不能代替执行检查。

### 9.2 权限目录建议

| 权限 | 作用域示例 | 默认策略 |
| --- | --- | --- |
| network.request | origin、路径前缀、方法、连接 | 使用时授权，禁止任意域名默认通行 |
| network.private | 具体局域网 origin 或用户选定设备 | 独立授权，不包含整个网段 |
| network.discovery | 指定发现协议与设备类别 | 用户主动发起，限制扫描规模 |
| credentials.use | 自有连接、认证配置、目标 origin | 允许代用，不返回明文 |
| credentials.read | 自有凭据的明确字段 | 高风险例外，默认关闭 |
| library.read | 已选歌单、选中资源或整个音乐库 | 小范围优先，整个库单独说明 |
| library.write | 指定歌单、append/create/update 等操作 | 导入计划确认后发操作租约 |
| library.delete | 指定资源与删除计划 | 独立权限，提供恢复机制 |
| player.read | 当前曲目、进度、队列等字段 | 按字段与使用场景授权 |
| player.control | 播放、暂停、跳转、改队列 | 用户动作或明确后台授权 |
| playback.fallback.hold | 自有解析器、当前操作 | 可选，受最大期限限制 |
| files.read | 用户选中的文件或目录句柄 | 系统选择器授予，不交出整个磁盘 |
| files.write | 用户选中的目标及写入方式 | 覆盖与删除另行确认 |
| downloads.create | 所选资源、目标目录、并发上限 | 独立于在线播放 |
| clipboard.read | 本次粘贴动作 | 不允许后台监听 |
| clipboard.write | 本次复制内容 | 用户动作，受长度限制 |
| notifications.system | 通知类别与频率 | Host 授权且受 OS 权限约束 |
| external.open | 具体 URL 或声明站点 | 用户点击后经 Host 打开 |
| background.run | 任务类型、连接、运行预算 | 默认不开启 |
| services.consume | 导出服务、方法与资源范围 | 按跨插件契约检查 |
| sharing.publish | 指定资源、分享模式、期限与可见性 | 用户确认计划后发布，不包含插件代码或个人主凭据 |
| sharing.revoke | 当前用户/插件拥有的分享记录 | Host 验证所有权，不能撤销其他用户的分享 |
| guests.manage | 当前父插件的子插件安装、配置、启停 | 安装由用户批准，不能管理其他父插件的子项 |
| guests.run | 已批准子插件及其固定内容版本 | Host 分配独立运行身份与配额 |

私有限额存储、自有日志、读取自己的权限状态、注册已声明的普通界面等属于基础隔离能力，不需要反复弹窗。基础能力仍有配额和数据隔离，不等于拥有系统资源权限。

通用 shell、任意本机程序执行和不受限文件 API 不进入普通插件 SDK。少数确有需要的设备能力应由可信系统适配器提供窄接口，而不是增加一个万能 system.exec 权限。

### 9.3 什么时候弹出授权

| 时机 | 行为 |
| --- | --- |
| 安装 | 展示身份、功能、声明权限与当前端能力；可选择安装后再配置 |
| 用户点击功能 | 根据真实目标和操作，合并申请必要权限 |
| 首次调用受限 API | 有有效用户意图时申请；无意图则返回待授权状态 |
| 注册/启动阶段 | 可声明需求、查询状态并排队，默认不抢焦点弹窗 |
| 用户在安装页选择“安装并配置” | 将首次配置视作前台操作，可进入受控授权流程 |
| 后台任务缺权 | 暂停该功能，留下可处理状态，不循环弹窗 |

这样支持用户提出的“安装、点击、用到权限、注册时申请”，同时避免安装十个插件后连续弹出十组窗口。

### 9.4 弹窗应让用户看懂

示例：

~~~text
Navidrome 音乐库 请求访问
发布者：example-community · 已验证签名

目标： https://music.example.com:443/rest/
用途： 搜索你的音乐并读取播放地址
会发送：搜索词、账号认证信息
不会自动扩展到其他服务器

允许本次连接 / 仅本次会话 / 记住此服务器 / 拒绝
查看详细范围
~~~

来源、范围、风险级别由 Host 生成。插件可以提供用途说明，不能修改可信标题、伪造系统权限状态或隐藏目标地址。

界面同时提示“哪些功能会受影响”，让拒绝结果可理解。拒绝后提供重新配置入口，不持续诱导。重复请求按插件与权限范围去重、退避。

### 9.5 授权身份与有效期

Grant 至少绑定：

~~~text
发布者信任身份 + 插件 ID + 用户配置空间 + 当前设备
+ 连接/资源范围 + 操作集合 + 有效期 + 授权修订号
~~~

- 单次授权绑定 Operation，允许其声明的有限子请求，不是一个可无限重复使用的布尔值。
- 会话授权随应用会话结束失效；持久授权也可随时撤销。
- 权限不因账户同步自动带到另一台设备；文件句柄和局域网范围尤其需要本机重新确认。
- 用户更换连接地址、插件扩大范围、发布者信任身份改变时，旧授权不能自动覆盖新目标。
- 同一身份的兼容更新可沿用未改变范围的授权；新增范围处于待授权。

撤权立即阻止新调用，并撤销相应句柄、取消可取消请求、关闭相关资源；已发送到远端的数据无法收回。正在写入的事务在安全检查点取消或完成最小原子步骤，并向用户说明结果。

### 9.6 插件查询与申请权限的 API

~~~typescript
const state = await ctx.permissions.query({
  key: 'server',
  scope: resolvedServerScope
})

if (state.status !== 'granted') {
  const result = await ctx.permissions.request({
    key: 'server',
    scope: resolvedServerScope,
    intent: ctx.operation.userIntent
  })
  if (result.status !== 'granted') {
    return { status: 'permission-required' }
  }
}
~~~

返回状态建议为 undeclared、prompt、granted、denied、expired、restricted、unavailable。撤权事件带 revoked 原因，随后 query 返回相应拒绝状态。

规则：

- 只能查询自己的授权摘要，不能枚举其他插件的权限、账号或凭据。
- request 不能突破 Manifest 上限；未知权限名在安装或校验阶段报错。
- userIntent 是 Host 产生的短期操作凭据，不能由插件通过传 true 或伪造点击获得。
- Host 渲染组件的真实交互可直接建立意图；高级 Web Surface 的合成消息不能自动视作可信点击。
- 权限 UI 等待超时返回拒绝/取消，无后台界面时返回 prompt-required，均不能默认允许。
- query 只是提示；真正执行仍检查，解决“查询后撤权、调用前仍显示 granted”的竞态。

## 10. 安全模型与能力代理

### 10.1 威胁模型

默认考虑以下情形：插件主动恶意、依赖被投毒、发布账号被盗、正常插件处理恶意返回数据、第三方页面诱导授权，以及插件崩溃或无限循环。

| 风险 | 主要控制点 |
| --- | --- |
| 读取本机文件、环境变量、系统凭据 | 受限运行时、OS 隔离、句柄式文件 API |
| 越权操作其他插件或账号 | 实际 sender 身份、连接作用域、不可伪造句柄 |
| 偷发数据、扫描内网 | 网络代理、目标范围、私网独立授权、访问审计 |
| 伪造系统弹窗、窃取密码 | 可信授权层、凭据组件、固定来源标识 |
| 通过封面/SVG/富文本执行代码 | 静态资源清洗、内容类型校验、CSP、大小限制 |
| 无限循环、内存暴涨、弹窗轰炸 | 执行中断、配额、队列、公平调度和隔离熔断 |
| 安装/更新供应链攻击 | 静态清单、签名、精确摘要、权限差异、撤销与回滚 |
| 以服务依赖为跳板借用特权 | 导出方法白名单、调用链身份和委托范围检查 |

权限控制可以减少滥用，但不能单独判断插件提供的内容是否合规，也不能保证一个已签名插件一定安全。用户授权说明“允许访问”，不意味着对内容权利和服务条款的证明。

### 10.2 网络代理

网络必须经过统一 Broker；普通插件不能自行打开 TCP、UDP、WebSocket 或绕过代理的浏览器 fetch。后续支持 WebSocket 时也使用相同的目标授权、连接寿命和配额。

代理负责：

1. 规范化协议、主机、端口、路径与国际化域名；拒绝混淆地址和不支持的 URL scheme。
2. 匹配精确授权，路径前缀按路径边界处理，不能让 /api/ 匹配到 /api-evil/。
3. 检查 DNS 解析结果，并在真实连接时约束最终地址，防止校验与连接之间的 DNS 重绑定。
4. 每次重定向重新检查目标；跨 origin 不自动携带认证头、Cookie 或凭据。
5. 默认阻止回环、链路本地、云元数据等敏感地址；局域网服务只能通过独立的具体目标授权访问。
6. 将媒体、封面、字体、同步、下载等隐含访问纳入同一规则。
7. 隔离 Cookie、代理配置和认证会话；不共享 Host 或其他插件的浏览器登录态。
8. 限制并发、响应体积、HTTP 解压后体积、重试和连接时间；记录脱敏访问摘要。

Navidrome 的局域网使用应顺畅：

- 用户主动输入的具体私网服务器可以申请 network.private，不能一键获得整个内网。
- 主机名解析到私网时同样需要私网授权，不能只判断地址字符串是否以 192.168 开头。
- 局域网 HTTP 是单独、可识别的连接配置，明确展示传输方式；不因此允许所有明文站点。
- 自签名证书采用具体连接的证书信任流程；不能给插件一个全局“忽略 TLS 错误”开关。
- 证书、目标地址或安全属性改变后重新验证；服务器发现不是自动授权连接。

### 10.3 凭据与用户数据

普通 API 返回凭据引用，由网络代理向已授权目标代用。为常见认证模式提供经过审核的认证配置；涉及特殊签名时，优先扩展窄化的签名能力，不直接把密码发给 UI。

若某协议确实必须让逻辑读取自有凭据，应申请独立的 credentials.read，清楚说明读取字段与用途。不能声称这类授权后仍可绝对防止插件复制秘密。

私有存储按插件、用户配置和连接隔离。Electron Host 使用当前桌面系统的密钥保管能力；不把渲染器 localStorage 或普通 JS 加密包装成系统级密钥保险箱。

用户音乐库操作通过数据服务，不暴露数据库连接或 SQL。读取范围可以是本次选中项目、某个歌单或整个库，写入分为创建、追加、修改和删除。

同时具有 library.read 和 network.request 的插件可能将已读取数据发送到获准站点。细粒度权限能缩小范围，但不能自动理解所有请求的真实用途；安装与授权页应解释这种能力组合，并允许查看实际访问记录。

### 10.4 文件与资源

文件选择器返回句柄，句柄绑定允许的操作、有效期与目录边界；相对路径必须归一化。检查符号链接、Windows junction/reparse point、大小写别名和实际最终目标，不能只比较路径字符串前缀。

导出采用临时写入后原子替换；覆盖已有文件需要明确授权。插件缓存有配额与自动清理规则，不允许借缓存无限写盘。

日志默认脱敏查询参数、认证信息、Cookie 和凭据。诊断导出由用户触发，并预览将包含的数据；不把敏感信息放进错误弹窗或埋点。

### 10.5 配额与降级

以下是首轮工程验证的起始值，不是已经测得的性能指标：

| 项目 | 建议初值 | 超出时行为 |
| --- | --- | --- |
| 单逻辑实例堆内存 | 64 MiB，可按能力档调整 | 中断并隔离，记录原因 |
| 连续 CPU 执行片段 | 100 ms 观察、500 ms 强制中断 | 保护界面与播放器响应 |
| 普通 RPC 载荷 | 256 KiB | 要求分页或流式传输 |
| 同连接网络并发 | 4 | 排队并公平调度 |
| 搜索总截止时间 | 8 秒 | 返回已完成结果，标记未完成来源 |
| 单次播放解析截止时间 | 10 秒 | 进入失败决策 |
| 自动候选解析 | 最多 3 个，总预算 20 秒 | 停止循环并交给用户 |
| 播放故障交互等待 | 最多 60 秒 | 取消本次等待，保留手动操作 |
| 私有持久存储 | 20 MiB 基础配额 | 提示清理或申请明确扩展 |
| 插件通知 | 去重且限制突发频率 | 合并到消息中心 |

CPU 时间、网络等待和用户授权等待分别计量。等待用户时不能占住整个插件调度队列；流式媒体和批量任务采用独立预算，不套用普通 RPC 的体积限制。

## 11. 插件影响默认行为：429、卡密过期与换源

### 11.1 将“报错”升级为结构化结果

不要让 Host 从错误字符串中猜测是否要换源。统一的 MusicFault 包含：

~~~typescript
interface MusicFault {
  code:
    | 'RATE_LIMITED'
    | 'AUTH_REQUIRED'
    | 'ENTITLEMENT_EXPIRED'
    | 'NOT_FOUND'
    | 'REGION_UNAVAILABLE'
    | 'NETWORK_ERROR'
    | 'PERMISSION_DENIED'
    | 'UNSUPPORTED'
    | 'CANCELLED'
    | 'INTERNAL'
  message: string
  retryAfterMs?: number
  retryable?: boolean
  recovery?: {
    mode: 'default' | 'retry-later' | 'await-user' | 'stop-current'
    maxWaitMs?: number
    actions?: Array<
      | { kind: 'retry'; label?: string }
      | { kind: 'choose-source'; label?: string }
      | { kind: 'cancel'; label?: string }
      | { kind: 'plugin-command'; commandId: string; label: string }
    >
  }
}
~~~

ENTITLEMENT_EXPIRED 表示插件所连接服务报告的使用资格过期，涵盖用户描述的卡密情形。Host 不把它展示成“Ceru 会员过期”，也不替该服务背书。

SDK 可暴露 ctx.playback.failure(...) 构造上述失败结果。它在当前解析调用的上下文中使用，**将错误与恢复建议作为同一个返回值提交**，避免“先报错，自动换源已开始，随后才收到阻止消息”的竞态。

### 11.2 429 示例

以下为解析器内部的示意代码：

~~~typescript
if (response.status === 429) {
  return ctx.playback.failure({
    code: 'RATE_LIMITED',
    message: '此来源请求过于频繁，请稍后再试。',
    retryAfterMs: parsedRetryAfterMs,
    recovery: {
      mode: 'await-user',
      maxWaitMs: 60000,
      actions: [
        { kind: 'retry', label: '稍后重试' },
        { kind: 'choose-source', label: '选择其他来源' },
        { kind: 'cancel', label: '取消' }
      ]
    }
  })
}
~~~

这是一个**覆盖建议**。Host 将它关联到真实调用的 Provider、Connection 和 Operation，检查 playback.fallback.hold 权限及用户策略后，才决定是否暂停自动换源。

当音乐清单或分片在播放阶段返回错误时，媒体 Broker 先记录实际错误，再调用拥有该媒体租约的故障处理器，使用相同协议。处理器超时、崩溃或版本已失效时直接采用 Host 策略，不等待任意插件响应。

### 11.3 仲裁优先级

从高到低：

1. 用户明确的停止、取消、手动换源，以及权限撤销。
2. 安全边界、来源隔离、资源预算和防循环规则。
3. 用户为该来源设置的故障策略，例如“允许先提示”或“始终使用已授权候选来源”。
4. 当前解析器在权限范围内返回的恢复建议。
5. 用户选择的播放策略插件提出的建议。
6. Host 默认失败策略。

不得开放全局的 preventDefault() 让任意插件截停其他来源。需要跨来源策略时，由用户选择一个角色型“播放策略提供者”；它只能接收必要错误摘要，其建议仍受以上优先级约束。

### 11.4 标准处理规则

| 错误 | 默认行为 | 插件可请求的交互 |
| --- | --- | --- |
| RATE_LIMITED | 对当前连接进入冷却；按用户策略决定是否尝试其他候选 | 有权限时先等待用户决定 |
| AUTH_REQUIRED | 暂停使用当前连接；不自动反复登录 | 打开已声明的连接命令 |
| ENTITLEMENT_EXPIRED | 标记当前连接不可用，解释第三方服务状态 | 打开该插件的管理页面 |
| NOT_FOUND | 若允许跨源匹配，尝试有限候选 | 展示匹配结果或放弃 |
| REGION_UNAVAILABLE | 停止当前来源；仅考虑用户许可且可用的其他来源 | 说明不可用原因 |
| NETWORK_ERROR | 有预算时退避重试，再执行来源策略 | 提示检查服务器 |
| PERMISSION_DENIED | 结束越权操作 | 提供权限设置入口，不通过另一插件代为绕过 |
| CANCELLED | 结束当前操作 | 不弹窗、不重试、不自动换源 |
| INTERNAL / UNSUPPORTED | 记录并隔离故障能力 | 合理降级或进入用户选择 |

Retry-After 是冷却依据之一，需要支持秒数和 HTTP 日期。对当前服务不早于有效的服务器冷却时间重试；异常或超长值可将来源置为待手动恢复，不能为了限时而提前请求。UI 等待期限与服务冷却期限分开。

### 11.5 防止插件劫持播放器

- 等待权仅作用于本插件当前正在服务的解析操作，不能锁住全局播放器。
- 同一故障只产生一个去重交互卡片或弹窗，Host 必须提供取消和来源选择。
- 用户离开播放请求、停止、禁用插件或撤权时立即释放等待。
- 交互等待达到上限后，默认取消本次播放尝试并显示可重试状态；不因超时偷偷执行插件原本要求暂停的自动换源。
- 明确采用“始终自动换源”的用户策略时，插件仅能提供提示，不能反复恢复等待。
- 同一操作记录已尝试候选，限制总次数与总时长，禁止来源 A/B 来回循环。
- 用户主动“重试”创建新操作；插件不能自己制造新操作以刷新等待上限。
- 弹窗消失、应用进入无界面后台等情况均结束阻塞，转为通知中心中的可处理状态。

“选择其他来源”只使用用户已允许的其他服务，不能实现轮换账号、隐藏代理等方式来绕过同一服务的限额。

### 11.6 卡密过期的推荐体验

插件返回 ENTITLEMENT_EXPIRED，附带已声明的账号管理命令。Host 显示：

~~~text
某音源插件报告：此服务的使用资格已过期。
该提示来自：某音源插件 / 当前账号

打开插件账号页    选择其他来源    取消
~~~

插件可通过通知、消息中心、局部状态和受控对话框说明问题。需要外部管理页面时，通过 external.open 在用户点击后打开明确 URL；不自动打开付费页面，不把外部页面伪装成 Host 授权窗口。

## 12. 事件、服务与 RPC 契约

### 12.1 三种交互不要混用

| 机制 | 使用场景 | 特性 |
| --- | --- | --- |
| Event | 状态通知，如连接断开、列表更新 | 不可取消业务决策，默认不阻塞 |
| Command / Service | 有明确输入输出的能力调用 | 有截止时间、取消、权限与结果 |
| Decision Hook | 当前操作需要策略建议 | 输入有限、输出枚举化、Host 仲裁 |

例如“曲目已变化”是 Event，“导入这个歌单”是 Command，“解析失败是否先询问用户”是 Decision。不要让一个全局事件总线承载任意业务控制和权限管理。

### 12.2 线路协议

每个请求至少携带 protocolVersion、requestId、operationId、method、payload、deadline 和 traceId。真实 plugin identity、module、connection、generation 由 Host 依据连接绑定，不能使用来包自报值作为鉴权依据。

- 请求和响应均做 Schema 校验、载荷限制和方法白名单检查。
- 只传受限 JSON、二进制块与 Host 句柄，不传函数、原型、Host 对象。
- 取消消息由 requestId 关联；服务必须可响应取消。迟到响应不得修改已经结束的操作。
- 流式查询使用 sequence、背压、终止消息和有限缓冲，不能向 UI 无限制推送。
- 错误码稳定，调试栈仅在本地诊断中按权限展示。
- 默认不自动重试写操作。可重试写入必须携带 idempotencyKey。
- 记录读写的权限修订号，在落地资源时检查最新状态，防止撤权竞态。

ctx.operation 只在 Host 发起的具体调用中存在；激活上下文没有可凭空用于授权的用户意图。SDK 可以提供相同外观的代理，但不能混淆两种上下文。

### 12.3 插件依赖与服务共享

Manifest 分别声明“包依赖”和“服务协议依赖”：

- 包依赖在安装阶段解析、锁定版本与摘要，展示每个发布者及其独立权限。
- 服务依赖声明协议版本、必需/可选、单提供者/多提供者和选择规则。
- 同协议有多个实现时，使用用户选择或明确作用域绑定，不能由后加载者静默覆盖。
- 私有服务默认仅包内可见；公开服务必须声明输入输出和允许消费的动作。

跨插件调用同时检查：

1. 消费者是否可调用该服务及其资源范围。
2. 提供者是否拥有实际执行操作的权限。
3. 当前委托是否允许这类输入、输出与后续访问。

这不是简单继承权限。例如 UI 插件可被允许调用搜索服务而无需获得底层服务器密码，但搜索服务不能因此提供任意 URL 转发、任意文件读取等通用特权代理。

调用链携带真实发起者，禁止依赖插件把拒绝的操作换个身份重试。组合包不共享一个“总授权”，也不允许子插件继承父插件未明确委托的能力。

### 12.4 可玩性与组合预设

逐步支持可视化动作编排，例如：

~~~text
用户触发“导入并整理”
→ 导入器解析选定歌单
→ 去重服务生成建议
→ 用户确认写入计划
→ 歌单服务执行
→ 封面插件更新展示
~~~

编排只连接已声明动作与事件，沿用权限、预算、审计和取消链。默认不允许事件循环；高级循环必须有次数上限。分享的是版本化配置预设，不是自动安装和自动授权指令。

## 13. 寄生插件关系：以 LX 兼容器为例

### 13.1 目标体验与职责

Ceru v2 **不原生识别 LX 脚本、LX 事件名或 LX 平台列表**。用户先安装一个普通澜音插件“LX 兼容器”，它同时包含可见和不可见模块：

- 可见部分：在设置中增加“LX 插件”页面，提供导入、管理、启停、更新和错误说明；补齐搜索来源 UI、音质选择及其他必要界面。
- 不可见部分：解析 LX 格式、实现其兼容 API、转换音乐数据、衔接搜索能力与播放解析。
- Host：负责通用子插件登记、安装确认、执行隔离、授权、资源配额和父子生命周期。

用户进入兼容器页面安装 LX 脚本后，可以获得熟悉的使用形式；不安装兼容器时，Host 没有 LX 专用页面和格式处理代码。

~~~mermaid
flowchart TB
  H["Ceru Host：通用扩展协议与 Guest 管理"]
  P["澜音原生插件：LX 兼容器"]
  UI["设置中的 LX 管理页、搜索 UI、音质选择"]
  CAT["兼容器的搜索与目录能力"]
  G1["Guest A：LX 脚本 A / 独立隔离身份"]
  G2["Guest B：LX 脚本 B / 独立隔离身份"]
  B["Host 能力代理与权限裁决"]
  H --> P
  P --> UI
  P --> CAT
  P -.->|"管理与协议适配"| G1
  P -.->|"管理与协议适配"| G2
  H -->|"创建与回收运行单元"| G1
  H -->|"创建与回收运行单元"| G2
  G1 -->|"子插件身份的 RPC"| B
  G2 -->|"子插件身份的 RPC"| B
  CAT -->|"父插件自己的权限"| B
~~~

推荐对用户使用“兼容器 + 子插件”的称呼，架构上称为寄生关系。它与普通依赖不同：子插件不能脱离对应兼容器运行，兼容器负责理解它的格式，但不因此拥有替它授予权限的权力。

### 13.2 搜索由谁提供

LX 当前公开自定义源协议主要围绕初始化、事件请求、音乐地址等能力；不能假设一份 LX 自定义源脚本自动具有完整搜索功能。兼容器应根据实际声明做能力映射，缺少的搜索和界面由兼容器自己提供，或依赖另一个经授权的标准搜索服务。[LX 官方自定义源说明](https://lxmusic.toside.cn/desktop/custom-source)

因此推荐链路为：

~~~text
Host 搜索框
→ LX 兼容器贡献的搜索 Provider / UI
→ 兼容器的目录适配层返回通用 ResourceRef
→ 用户选择播放
→ 兼容器为该资源选择一个已启用的 LX Guest
→ Guest 解析地址
→ Host 媒体代理校验并播放
~~~

兼容器内部可以理解 tx、kg 等旧标识，并补齐相应图标与数据查询。Host 只看到标准 Provider 与不透明资源引用，不增加 LX 专属平台枚举。

多个 LX 子插件支持相同来源时，兼容器提供“此来源默认使用哪个子插件”的绑定界面。Host 保存用户选择，并允许查看实际执行者。子插件只提供地址解析时，不虚构它拥有搜索能力。

数据资源身份与执行者身份分开：搜索得到的歌曲引用可以属于兼容器目录；本次选择哪个 Guest 解析是 ExecutionRef，不应因为换了 LX 脚本就使已保存歌单全部失效。

### 13.3 Host 提供通用 Guest API

Guest Manager 只理解“某父插件托管的、固定内容版本的外部可执行模块”，不理解 LX 格式语义。

兼容器 Manifest 声明：

~~~json
{
  "contributes": {
    "settingsPages": [
      {
        "id": "lx-manager",
        "title": "LX 插件",
        "view": "lx-manager"
      }
    ],
    "guestAdapters": [
      {
        "id": "lx-script",
        "format": "lx-custom-source",
        "compatibilityProfile": "desktop-basic@1",
        "bootstrap": "guest.lx-bootstrap",
        "runtime": "ceru-js@1",
        "projectableProtocols": [
          "music.resolve@1",
          "music.lyrics@1"
        ]
      }
    ]
  },
  "guestPolicy": {
    "maxDepth": 1,
    "allowedCapabilities": [
      "network.request",
      "storage.private",
      "playback.fallback.hold"
    ],
    "networkScopeMode": "per-guest-user-approved",
    "allowNativeCode": false,
    "allowRemoteCodeExecution": false
  }
}
~~~

这是补充字段示例，不是完整 Manifest。compatibilityProfile 是兼容器自定义并维护的兼容档位版本，不冒充 LX 官方版本号。allowedCapabilities 是可委托的能力上限，其中 storage.private 是限定基础能力；它们均不直接产生授权，也不意味着父插件获得这些能力的全局使用权。

拟议 API：

| API | 职责 |
| --- | --- |
| ctx.guests.registerAdapter | 实现 Manifest 中声明的格式检查与协议映射 |
| ctx.guests.prepareInstall | 从用户选择的文件/URL 句柄创建待安装记录 |
| ctx.guests.requestInstall | 由 Host 展示子插件身份、内容和权限计划，取得批准 |
| ctx.guests.list / inspect | 查询本父插件的子项、版本、授权和健康状态 |
| ctx.guests.start / stop | 请求运行或停止已批准的固定版本 |
| ctx.guests.invoke | 使用 Host 句柄调用获准的子插件协议 |
| ctx.guests.project | 将获准的子插件能力投影到声明的原生扩展点 |
| ctx.guests.prepareUpdate | 创建新版本比较与批准流程 |
| ctx.guests.remove | 移除子项，按用户选择清理数据与凭据 |

接口返回 Host 发放的句柄，不接受父插件通过字符串任意指定另一个插件的身份。安装入口可由父插件完整定制，但最终执行批准始终由可信 Host 展示。

### 13.4 兼容环境由父插件交付，执行权由 Host 管理

LX bootstrap 是父插件单个 .js 文件中的独立模块入口，用于在 Guest 环境内建立兼容对象、事件和工具方法。它与子脚本一起在 **Guest 的身份和权限** 下运行，不携带父插件的 ctx、网络令牌或用户数据句柄。

Host 按以下结构创建执行单元：

~~~text
Guest Runner
  固定版本的受限引擎
  + 已校验父插件单文件中的指定兼容 bootstrap
  + 已批准摘要的 Guest 脚本
  + Guest 专属能力代理
~~~

Guest 的网络请求直接进入 Host Broker，并保留 Guest 身份。不能让子脚本把 URL 发给一个持有父权限的通用 fetch 函数，再由父插件代为请求。

父子之间只交换受 Schema 约束的协议消息。子插件不能读取父插件或兄弟子插件的内存、存储、凭据和全局变量。

兼容层可以模拟原格式的 API 外观，但不能模拟出其原本拥有的所有特权。无法满足的 API 应明确返回不支持；当前只验证 Electron 支持范围，网络请求统一走 Host Broker。

不能通过静态检查证明任意 JavaScript 父插件永远不会自行编写解释器。因此安全设计依靠 Host 不自动扩大父权限、子权限不交给父插件、限制父插件输入输出，并审核兼容器的行为；不把“它声称自己是兼容器”作为信任依据。

### 13.5 子插件安装与身份

原格式脚本可能没有签名、Manifest 或权限声明。兼容器可解析名称、版本与作者信息，但这些都属于未经验证的自报元数据。

Host 为每个子插件建立记录：

~~~text
guestId：稳定安装 ID
parentPluginId：父兼容器身份
adapterId / adapterVersion：兼容规则
artifactDigest：实际脚本内容摘要
bootstrapDigest：所使用的兼容层内容摘要
claimedMetadata：原格式自报名称、作者、版本
verifiedPublisher：有验证证据时才填写
grants / storageNamespace / runtimeState：Host 管理
~~~

父插件签名有效，不代表其导入的子插件有可信签名。授权页必须区分显示，例如：

~~~text
LX 兼容器 → 测试音源 A
兼容器发布者：已验证
子插件作者：脚本自报，未验证
本次内容摘要：……
将申请：访问 api.example.com
~~~

单个 JS 文件作为 Guest artifact 导入时，内容进入 Host 安装记录并绑定摘要，不在启动时直接加载可变化的远端脚本。原格式依赖其他代码文件时，应由兼容器的构建工具先合并成一个可检查的子脚本；不能在运行时补下载未批准代码。

安装前不执行子脚本来获取元数据。确需运行才能发现能力时，在用户同意安装后进入无外部能力的探测阶段；动态发现结果只形成申请，不能形成授权。

### 13.6 没有原生权限声明的脚本如何申请权限

兼容器静态分析可提供已知域名建议，但不能宣称它找到了所有潜在目标。旧脚本可能动态计算地址。

推荐流程：

1. 导入预览展示能确定的目标，以及“可能在首次使用时申请其他目标”。
2. 第一次真实网络请求到达 Host 时，按 Guest 身份暂停并申请精确范围。
3. 如果当前没有用户操作上下文，返回待授权并在兼容器页提示，不能在后台无限弹窗。
4. 授权后继续该操作；后续新增目标重新申请。
5. 原脚本只支持回调时，由兼容桥转换等待、拒绝、超时与取消，不丢失 Host 操作上下文。

有效的子插件访问范围为：

~~~text
本次请求范围
∩ 用户授予该 Guest 当前版本的范围
∩ 父兼容器声明的委托上限
∩ 当前操作范围
∩ Host 与平台允许范围
~~~

父插件自身的授权与 Guest 授权互不转移。兼容器为自己实现的搜索请求使用父身份；子插件解析播放地址使用 Guest 身份。允许托管一个音源插件，不等于给兼容器授予所有子插件站点的访问权。

用户可单独撤销“测试音源 A”的域名访问，而不影响“测试音源 B”或父插件自己的搜索功能。凭据、限流、通知与审计均支持这种粒度。

### 13.7 扩展投影与可见页面

寄生插件不直接篡改 Host 注册表。父插件通过 project 将已批准的能力转换为原生贡献，Host 同时记录：

- UI/协议提供者：哪个父插件。
- 实际执行者：哪个 Guest、哪一版内容和哪条连接。
- 数据提供者：搜索结果或目录来自谁。
- 作用范围：哪些插槽、Provider 和当前操作。

父插件可以为子插件展示独立配置卡片、来源选项与状态徽标。最终授权窗口和实际执行者提示不能被父插件覆盖或隐藏。

子插件的通知、更新提示和异常统一转为 Host 的结构化消息。LX 更新事件只能触发待处理更新建议，不能直接替换脚本；无法可靠识别的错误不能凭字符串猜成“用户必须付费”。

子插件产生 429 时，Host 按该 Guest/连接冷却；兼容器映射为第 11 节的故障协议。等待换源权限也绑定 Guest 与本次操作，不能借父插件已获准弹窗就无限阻塞。

### 13.8 父子生命周期

| 行为 | 结果 |
| --- | --- |
| 禁用父插件 | 所有子项停止，投影贡献撤回，保留安装记录 |
| 父插件崩溃 | 子调用取消并释放资源；恢复后按启用状态和权限重新激活 |
| 禁用一个子插件 | 只撤下它的能力，其余子项与父搜索功能继续可用 |
| 子插件崩溃 | 只隔离该子项，兼容器页面可显示原因并重启 |
| 卸载父插件 | 展示受影响子项；可保留隔离归档或一并删除，不允许子项悬空运行 |
| 重装同一可信父插件 | 可重新关联归档，但重新检查版本、摘要与授权有效性 |
| 换用另一个兼容器 | 视作新的父子信任关系，不默默继承旧授权 |
| 更新子脚本 | 固定新摘要，先比较和批准，再替换运行版本 |
| 更新父兼容器/bootstrap | 验证子脚本兼容性及委托变化，必要时重新授权，失败可回滚 |

对未签名子脚本，内容发生变化即需要新版本批准，不能仅凭文件名、作者文本或版本号继承信任。逻辑 guestId 可以保持稳定以保留设置，运行批准仍绑定新摘要。

第一版只允许一层父子关系，每个 Guest 只属于一个父插件。不允许 Guest 再创建 Guest，不允许循环寄生。相同脚本分别导入两个父插件时是两份独立安装记录。

CPU、内存、网络、弹窗和活跃子项数量同时受 **单 Guest、父子树、整个用户配置** 三层预算控制，避免通过不断创建子项放大资源额度。

### 13.9 第一版兼容范围

LX 兼容器应公布明确的 API 支持矩阵：已支持、部分支持、不支持、仅某端支持。优先支持标准音源请求链、取消、所需纯计算工具和受控更新提醒。

“安装后与目前一样的使用形式”作为产品体验目标；不等于保证所有历史脚本、非公开 API、任意网络行为和各端环境细节完全兼容。不兼容时显示具体 API 和原因，不能默默提升权限解决。

这套机制也可被其他澜音兼容器用于托管另一种音源脚本或受限小工具格式，无需向 Host 加入新的格式专用逻辑。

## 14. 歌单导入、平台导入与后台任务

### 14.1 导入入口

导入器可以注入“导入歌单”按钮、上下文菜单、粘贴链接入口、文件入口和平台账号连接。Host 统一管理任务进度、取消、错误和恢复。

URL 识别分两步：

1. **本地识别**：对用户输入做纯字符串/结构解析，给出匹配候选和说明；不联网、不读取剪贴板。
2. **用户选择后的解析**：获得输入范围与网络授权，再读取远端数据。

多个插件都声称能识别同一链接时由用户选择，不能以最高自报置信度自动获得输入。剪贴板只在用户粘贴或明确点击读取时交给选定导入器。

### 14.2 导入协议

~~~text
recognize(input) → 候选说明
prepare(input, options) → ImportPlan
preview(plan) → Host 展示目标、数量、权限与冲突
commit(plan, approvalHandle) → ImportJob
cancel(job) / inspect(job) → 当前进度与部分结果
~~~

ImportPlan 至少包含来源、目标、新建/追加/覆盖类型、预估数量、重复项处理、失败处理、可能发送到远端的数据以及计划摘要。

approvalHandle 绑定确切的计划摘要、目标资源和允许操作。插件更换目标、扩大数量范围或把“追加”变成“清空后重建”时，必须生成新计划。

### 14.3 写入与可恢复性

- 本地音乐库尽可能在事务中提交；大量导入分批写入并保留恢复记录。
- 每批有幂等键和已完成游标，重试不重复插入。
- 覆盖或删除独立确认，保留撤销快照或回收站。
- 远端服务未提供事务时，明确采用分步执行和补偿；不能向用户承诺绝对原子。
- 取消后展示已完成部分，并允许按当前授权继续或撤销。
- 导入元数据不等于下载音频；下载需要另外的功能与授权。

### 14.4 后台任务

同步、扫描、预缓存等使用 Host Job API，声明用途、连接、资源预算、恢复能力和幂等策略。当前处理 Electron 关闭窗口但仍运行、系统休眠、断网及应用重启的状态，不把任务生命周期绑定到某个页面或一个永不结束的定时器。

任务保存的是可恢复的步骤与数据，不是挂起的 JS 调用栈。恢复时重新验证权限、连接状态和插件版本；权限失效时进入待处理状态。

## 15. 安装、分发、更新与生态治理

### 15.1 安装来源

支持官方索引、第三方索引、本地插件包、用户输入的 HTTPS 地址和分享链接。索引是发现机制，不是执行环境。

分享链接只打开安装预览，例如通过应用 deep link 定位包；不能因用户打开一个网页就自动安装或授予权限。插件包 URL 与摘要可携带在链接中，但仍必须校验实际下载内容和发布者信任。

普通用户安装签名 JS 发行文件；开发模式可导入本地未签名 JS，但有持续可见的开发标识，采用独立身份与数据空间。未签名文件仍受运行隔离和权限限制，不能覆盖已验证发布者的同 ID 插件。

### 15.2 安装向导

~~~text
1. 读取与校验
   单文件结构、摘要、签名、发布者、兼容性、依赖、资源上限
2. 功能预览
   将新增哪些来源、页面、按钮；是否建议替换默认角色
3. 权限解释
   必需与可选、具体用途、当前已知目标、哪些功能可后续授权
4. 用户决定
   安装 / 安装并配置 / 取消
5. 安装后配置
   选择服务器或账号，申请具体资源权限
6. 完成
   进入插件功能；同时保留权限与卸载入口
~~~

安装页不执行插件脚本，也不加载插件远端图标。预览素材来自已校验包，并在受限解析器中处理。依赖插件逐一展示身份和权限，不能隐藏在“主插件需要依赖”后面。

安装不等于启用所有功能；安装完成后，尚未配置的来源显示“连接后使用”，而不是不可解释的失败。

### 15.3 单文件校验与发布者身份

签名信息内嵌在同一个 .js 文件的静态头部，不要求用户同时下载 .sig 文件。采用固定版本的签名格式及成熟算法，例如 Ed25519。

普通发行模式的签名绑定规范化静态头与实际代码/资源载荷的摘要，签名值本身按规范替换为空值后计算，避免递归；算法、keyId、格式版本等其余字段仍被签名覆盖。规范须固定 UTF-8、内容边界、长度编码、JSON 规范化与域分隔，并提供测试向量，不能使用未经界定的字符串拼接。

动态发行模式使用第 16 节的“模板签名 + 发放签名”。两种模式由明确的协议字段区分，校验失败不能退回另一模式或按未签名文件继续安装。

校验重点：

- 限制原始文件、头部、AST、模块数量、资源数量和 Base64 解码后的总量。
- 拒绝重复字段/模块/资源 ID、非法注册结构、未声明入口和摘要不符。
- 所有模块、资源和授权相关静态数据必须被当前签名模式覆盖，不能留可执行的未签名尾部。
- 文件以 Host 分配的内部标识写入暂存区，原始文件名和资源 ID 不用于构造任意磁盘路径。
- 完成静态校验后原子保存一个发行文件；内部资源缓存由 Host 按安全 ID 管理，不进行归档解压。
- 清洗图片等衍生资源单独缓存并绑定已验证的原始资源摘要，不修改发行源文件。
- 不运行 postinstall，不在用户设备上解析不受锁定的 npm 依赖。

签名首先证明“包内容对应某个密钥”。将密钥绑定到发布者，还需要可信索引证明、已有信任钉扎或用户明确确认；包里自带一个公钥并不能自行证明官方身份。

发布者换钥需要可验证的轮换流程；无法建立连续信任时按新身份处理。显示名称相同不继承旧授权。

### 15.4 Host 管理更新

更新地址和渠道来自可信安装记录或已验证的静态分发元数据。Host 下载更新描述、校验签名、比较权限与兼容性，插件不参与决定“跳过验证”。

安装器为下载发行包产生的网络访问，与插件运行时网络权限分开；插件不能利用更新器作为任意网络代理，更新响应也不直接交给插件代码执行。

更新过程：

1. 下载新包到暂存区，完成所有校验。
2. 计算权限、发布者、依赖、扩展点和默认角色变化。
3. 按用户更新偏好安排切换；新增高影响权限未获批准前不激活相应功能。
4. 为插件私有状态创建版本快照，在受限迁移环境中验证新版本数据。
5. 等待可安全切换的时机，撤下旧注册，启用新实例。
6. 运行健康检查，失败则回到旧代码与兼容数据快照。

迁移代码只接触该插件自己的存储，仍有预算且默认无网络。迁移失败不损坏旧状态；不可逆变更需要提前明确说明和可恢复方案。

回滚不回滚用户撤权记录，不重新启用已吊销身份，不恢复用户已经删除的凭据。共享音乐库数据通过独立事务或操作记录处理，不能随意回滚整个应用数据库。

安全关键更新与撤销可阻止继续运行高风险版本；一般功能更新可由用户暂停或锁定。离线状态显示撤销信息最后更新时间，不能宣称离线时仍知道最新风险。

### 15.5 禁用、卸载与恢复

禁用会撤回贡献、停止后台任务并撤销运行租约。若正在播放该插件的资源，先让用户看到影响；用户明确要求立即禁用时停止相关访问。

普通运行崩溃与主动禁用区别处理：崩溃后，如果授权仍有效，已经由 Host 接管的媒体流可以持续到现有租约到期；需要刷新时采用故障策略。崩溃不能自动获得新权限。

卸载界面提供：

- 删除程序，保留插件设置以便重装。
- 清除缓存。
- 删除该插件凭据。
- 查看依赖哪些插件会因此不可用。

用户自己导入的歌单默认保留，并保留原来源标记。插件退出时不能擅自清空用户数据。

### 15.6 生态治理与分发体验

索引页面展示：发布者验证状态、源码/许可证、隐私说明、支持端、权限范围、更新记录、包摘要、审核时间和已知风险。

将标记分开：**身份已验证、包签名有效、通过某项检测、人工审核过**是不同事实；不要合并成一个模糊的“绝对安全”徽章。

提供举报、下架、发布者申诉、版本撤销和恶意包阻止列表。远程治理消息必须经过可信签名与范围约束，不能成为下发任意代码或修改用户数据的通道。

面向开发者提供模板、示例包、兼容性报告、可复现构建建议、依赖清单和发布检查。面向用户提供预览、截图、清晰的能力说明和一键恢复。组合预设可以分享“插件列表 + 版本约束 + 布局”，但每个包仍独立安装与授权。

## 16. 高性能动态生成：按用户发放一个 JS 文件

### 16.1 对现有模板的分析

根据本次提供的模板，可变内容集中在 PLUGIN_NAME、DESCRIPTION、VERSION、AUTHOR、API_URL、UPDATE_MD5、API_KEY 和 SOURCES；音乐地址解析、错误处理和事件结构基本相同。

建议保留“动态生成给用户”这一体验，改成 **固定核心代码 + 有限个性化数据 + 可验证的发放信息**。每个核心版本只编译一次；发放给不同用户时不再编译、压缩、解析或全文替换核心代码。

| 原模板字段/行为 | v2 建议归属 |
| --- | --- |
| PLUGIN_NAME、DESCRIPTION | 受模板规则约束的个性化显示字段 |
| VERSION、AUTHOR | 核心发行版本与发布者信息，通常随模板固定 |
| API_URL | 模板预声明范围内的配置；实际访问仍需用户授权 |
| SOURCES | 模板已有能力的配置、显示或启用子集，不能注入新代码 |
| API_KEY | 优先改为一次性激活信息；兼容时作为明确的敏感交付字段 |
| UPDATE_MD5 | 分离为核心版本/可靠摘要与授权状态；不把 MD5 当签名或授权证明 |
| 顶层 checkUpdate() | Host 根据静态更新描述调度，用户许可前不在安装时执行 |
| stopRequests 与通知 | 映射到当前操作的结构化故障，保留第 11 节仲裁规则 |

v2 原生发行文件使用第 6 节的静态描述与模块结构；现有 module.exports 脚本如需过渡，由明确的兼容器适配，不能为提取信息直接在 Host 运行它。

### 16.2 构建与发放是两条流程

~~~text
低频：开发者发布一个核心版本
源码 → CLI 构建 → 固定 JS 载荷 + 固定 Manifest
     → 生成模板摘要、签名和个性化规则
     → 存入内容寻址的模板仓库

高频：用户购买、领取或重新下载
验证订单/账号 → 获取已缓存模板
              → 生成少量个性化 JSON 与激活信息
              → 为本次发放签名
              → 流式输出：个性化静态头 + 原样核心 JS 载荷
              → 用户获得一个 source.js
~~~

服务器内部可以分开存储模板和发放记录，**用户得到的文件必须自包含**。不能只交付一个远程 loader，让安装器再下载主体代码。

npm CLI 后续可提供构建发行模板的命令，供售卖平台或发放服务使用；它与终端用户无关。普通插件也可直接输出一个不带个性化数据的签名 JS 文件。

### 16.3 明确哪些字段可以动态修改

模板签名必须覆盖 personalizationSchema 和发行方委托规则。允许动态变化的字段按类型、长度、枚举、目标范围和展示位置定义，拒绝任意键值覆盖 Manifest。

默认规则：

- 名称、描述、连接别名可以变；Host 始终保留真实发布者和稳定插件 ID 的来源标识。
- 展示名称不作为安装身份；同名文件、不同名称都不能绕过版本和发布者检查。
- 服务器地址只能在模板预先声明的范围内配置；最终 origin、路径和方法仍进入正常授权流程。
- 音源列表只能引用已编译的 Provider 模板或协议能力。新增程序逻辑、权限类别、Guest 委托范围和 UI 插槽需要重新发布核心模板。
- 代码版本、Host API 要求、签名发布者、入口和不可变权限上限不能由售卖后台随意覆盖。
- 个性化值作为数据传入模块实例，例如 ctx.config；不拼成可执行函数、import 或字符串代码。
- 展示数据与凭据分开投递。Host 解析敏感字段后导入该实例的凭据域，UI 和普通配置 API 只得到必要摘要或引用。

同一人可以安装多个连接或授权实例，但 Host 必须让用户选择“更新现有实例”还是“新增独立实例”。内部用稳定插件身份加本机实例 ID 区分，不用每次随机改 pluginId 逃避授权记录。

### 16.4 模板签名与发放签名

如果每次个性化都对完整大文件重新计算摘要并签名，仍会重复扫描全部代码。高频模式建议使用固定的 template-delivery@1 签名协议：

1. **核心载荷摘要**：构建时对完整、确定字节的 JS 模块表和资源表计算 codeDigest。
2. **模板证明**：发布者签名绑定 codeDigest、固定 Manifest、格式/运行时版本、个性化 Schema 和发行委托规则，得到 templateDigest。
3. **发放证明**：发行服务签名绑定 templateDigest 和本次完整个性化载荷，包括发放 ID、目标配置、显示字段、激活信息和有效期。
4. **单文件封装**：模板证明、发放证明和个性化数据都放进文件头，主体 JS 原样复用。

协议使用固定域分隔与规范化编码。所有影响执行、授权、身份和展示的数据必须落在上述承诺中；不允许把未签名字段当作有效配置，也不允许未签名的可执行前缀或尾部。

发布者可委托一个独立的在线发行密钥，只允许为指定模板和字段范围发放。核心发布密钥不必常驻售卖服务；发行密钥不能修改核心代码、扩大权限或伪装其他发布者。Host 校验完整委托链，而不是相信文件自带的任意公钥。

简化的个性化载荷示意：

~~~json
{
  "deliveryVersion": 1,
  "templateDigest": "sha256:TEMPLATE_DIGEST",
  "deliveryId": "delivery_opaque_id",
  "display": {
    "name": "我的专属音源",
    "description": "连接已开通的音乐服务"
  },
  "config": {
    "apiOrigin": "https://source.example.com",
    "enabledSources": ["catalog-a", "catalog-b"]
  },
  "activation": {
    "mode": "one-time-code",
    "code": "OPAQUE_REDEMPTION_CODE"
  },
  "issuedAt": "2026-09-18T00:00:00Z",
  "activationExpiresAt": "2026-09-19T00:00:00Z"
}
~~~

这只是待签名数据对象，最终仍内嵌在 .js 中。Host 计算实际载荷摘要、验证模板证明与委托、验证发放证明及字段约束后，才形成有效配置。文件声称的 codeDigest 不能代替对实际字节的检查。

普通单签名模式与分层签名模式各有明确语法与校验规则；分层验证失败不得降级成普通未签名导入。

### 16.5 高性能输出路径

发放服务预缓存不可变模板载荷、固定元数据、模板证明及约束校验器。热路径只做：

~~~text
身份/订单校验
→ 获取模板引用
→ 校验小型配置
→ 分配或复用幂等发放记录
→ 签小型个性化载荷
→ 生成文件头
→ 以背压控制顺序写入文件头与固定载荷
~~~

实现建议：

- 不在每个下载请求里运行 bundler、压缩器、AST 解析器或 npm 安装。
- 发行服务直接调用发行 SDK，并复用已加载模板与签名连接，不为每个用户启动 CLI/Node 子进程。
- 不对整个 JS 连续 replace 多个占位符。构建产物只留一个结构化个性化区域，主体不做替换。
- 原文件头按确定边界生成，个性化 JSON 可编码为 Base64URL 字段；避免名字中出现引号、换行或注释结束符就改变文件语法。Base64URL 只是编码，不提供保密。
- 如果保留用户熟悉的 @name 等可读注释，它们只是经转义生成的显示副本；Host 只信任已验证结构中的有效元数据，避免两个名称来源产生歧义。
- 使用共享只读 Buffer 或文件流输出主体，不为每个用户复制一整份大字符串。每请求仅持有小型头部和有限流缓冲。
- 热模板用有大小上限的缓存；大量模板可走文件流或对象存储流，缓存键绑定 templateDigest，禁止原位修改已签名载荷。
- 元数据和模板证明的规范化结果可缓存；订单状态、激活记录和发放数据不能误用跨用户缓存。
- 发放接口具备幂等键，相同授权请求重试可复用未失效的交付记录，避免生成多个互相冲突的一次性码。
- 授权校验、密钥签名服务和模板读取分别设超时、并发限制与监控；可水平扩展无状态发行节点。
- 模板主体可公共缓存；含个人配置/激活信息的最终下载响应使用 private、no-store 等适当缓存策略，不能进入共享 CDN 缓存。
- 下载鉴权和长期 API Key 不放在 URL 查询参数里；文件名、Content-Disposition 和日志中的用户数据需独立清洗。

若主体大小为 N、个性化大小为 D，发行阶段新增的序列化/摘要/签名工作应主要随 D 增长。输出完整文件仍有不可消除的 O(N) 网络传输，不能承诺整个请求为常数时间。共享固定载荷后，每请求内存主要为 O(D + 有限流缓冲)。

Host 安装新文件也仍要读取和验证实际代码字节。完成验证后，可按 codeDigest + runtimeVersion + SDK 档位复用解析/编译缓存，避免仅因名称或授权码不同就重新编译大段相同代码。不同实例的堆、存储、凭据和权限记录始终独立。

### 16.6 卡密与授权的两种模式

**推荐：交付一次性激活凭据。**

生成文件时仅写入可撤销、短期的一次性兑换码。用户首次主动连接并授予服务器访问权限后，由 Host 凭据代理向授权服务兑换该实例的访问凭据并保存。后续请求使用目标受限的凭据引用，可刷新、到期或撤销。

兑换接口应支持幂等恢复。若要限制买家或设备，必须在服务端验证买家账号或设备登记；一次性码本身不能防止“他人在首次兑换前拿走文件”。设备数量、解绑和换机应有用户可理解的流程。

**兼容：直接交付现有 API Key。**

可以把当前 API_KEY 作为签名个性化数据写入文件，并由 Host 导入凭据域后代用。这有利于对接现有接口，但原始 JS 文件里的 Key 仍可被复制；不能用混淆、Base64 或把解密密钥同时放进文件来宣称安全保密。

这种模式应使用每用户独立、可轮换和可撤销的 Key，由服务端限制资源范围、并发、有效期和账户权限。生成器不得写入服务端主密钥、发行私钥或全平台共享管理凭据。

付费资格由上游服务端验证。修改本地到期时间、音质列表或显示字段不能获得额外服务权限；文件签名说明内容来源，不等于服务端承认购买资格。

### 16.7 更新与授权续期分离

- **核心代码更新**：新模板、新 codeDigest，重新进行代码校验、兼容性检查及必要的权限审查。
- **授权续期/换 Key**：凭据服务更新该实例的凭据状态，或发放新的个性化封装；不编译相同核心代码。
- **改名/选择已有音源**：只更新被允许的数据字段；若产生新的网络目标，仍须重新授权。
- **发放信息到期**：区分激活码兑换期限、访问令牌期限和服务权益期限，不把它们混为插件程序版本到期。

代码更新描述保持可静态校验。资格查询使用受控认证请求，不沿用模板中将 key 放入检查更新 URL 的方式；解析结果、带令牌媒体 URL 和完整响应体默认不记录。

动态发放也可用于寄生插件：父兼容器的代码模板独立签名，Guest 的个性化数据仍绑定它自己的内容版本和授权身份。父级名字变化不能自动重置子级限流或撤权。

### 16.8 性能验证

至少测试小型音源模板与包含 UI 的较大模板，分别记录冷缓存/热缓存、不同并发量下的：

- 配置校验、签名、生成首字节时间及完整下载时间的 p50/p95/p99。
- 每次发放 CPU 时间、内存增量、模板缓存命中率与签名服务队列长度。
- 对相同核心生成大量不同名称/激活信息时的吞吐及隔离正确性。
- Host 首次安装与已验证核心缓存命中时的解析/编译耗时。

性能指标由实际运行环境测量确定。架构目标是消除逐用户构建和重复全文处理，不在没有测量前承诺固定的每秒发放数量。

## 17. 歌曲分享：分享能力与数据，不上传运行插件

### 17.1 目标架构

按当前描述，歌曲分享依赖上传 JS 并在服务器运行。v2 建议替换为 **客户端插件提供分享能力，分享服务保存标准数据，必要时调用明确的远端分享协议**。

插件发行与歌曲分享是两条链路：用户安装音源仍收到一个 JS 文件；分享歌曲产生链接或分享描述，不包含这个插件文件、个性化封装或用户凭据。

插件可实现 music.share@1，为其资源声明可用模式、生成分享草稿、申请分享授权并处理撤销。Host 的分享按钮通过能力发现调用它；分享服务不再提供上传插件执行入口。

~~~mermaid
flowchart LR
  P["发送者的客户端插件"]
  H["Host 分享代理：预览、权限、校验"]
  S["分享服务：数据记录、访问策略、通用协议"]
  V["接收者 / 分享网页"]
  R["可选：音源作者自己的分享解析服务"]
  C["可选：接收者本机插件"]
  P -->|"结构化分享草稿"| H
  H -->|"元数据与分享授权引用"| S
  V --> S
  S -->|"固定 share.resolve 协议"| R
  V -->|"在澜音中打开"| C
~~~

### 17.2 四种模式与推荐优先级

| 模式 | 插件需要提供什么 | 接收者体验 | 服务端责任与限制 |
| --- | --- | --- | --- |
| 信息/原站链接 | 歌曲元数据、可公开的原站地址 | 可查看和跳转，播放由原站决定 | 保存数据，无插件运行 |
| 接收端插件解析 | 稳定资源描述、标准协议、建议插件身份 | 在澜音中用自己的插件/账号播放 | 保存描述，不接收发送者凭据 |
| 委托解析服务 | 音源作者提供 share.resolve 协议与限定分享授权 | 可在网页播放，视权限可能需登录 | 调用登记过的协议端点，不执行上传代码 |
| 可公开媒体地址 | 明确允许公开分享且不含个人凭据的媒体引用 | 在有效期内网页直接播放 | 校验可用性、到期和来源，不保证永久有效 |

建议所有 Provider 至少可以降级为歌曲信息分享；客户端间分享优先使用接收端自己的能力。有网页播放需求的商业音源，可由作者增加标准分享接口，无需 Ceru 接管其插件实现。

第四种适合明确允许公开访问的媒体。原始解析结果不能自动当分享链接：它可能含用户 token、只在本机可用、很快过期或不允许再分发。

“任意私人音源 + 接收者没有插件/账号 + 没有远端服务 + 网页始终可播放”无法仅靠元数据实现。能力不足时应明确降级，不能回退到偷偷上传 JS。

### 17.3 客户端契约

拟议提供：

~~~text
music.share@1.capabilities(resource)
  → 可用模式、范围、有效期上限、接收者要求

music.share@1.prepare(resource, requestedPolicy, operation)
  → ShareDraft：元数据、播放方案、可能的成本/数据外发

Host share.preview(draft)
  → 用户确认内容、可见性、期限和授权方式

Host share.publish(draft, approvalHandle)
  → shareId、URL、撤销句柄

Host share.revoke(shareId)
  → 立即停用本服务链接，并请求上游撤销相关授权
~~~

prepare 只准备计划，不应提前公开分享或消耗不可撤销额度。确需向上游申请短期 grant 时，在用户确认后的提交阶段执行，发布失败则尽力撤销未使用 grant。

ShareDraft 必须分开标记公开字段、仅服务端可见字段及仅本机保留字段。Host 用允许列表构造发布载荷，不把插件返回的整个对象原样上传。

### 17.4 分享记录是数据协议

公开或可展示的数据示例：

~~~json
{
  "shareVersion": 1,
  "kind": "track",
  "metadata": {
    "title": "示例歌曲",
    "artists": ["示例艺人"]
  },
  "resource": {
    "namespace": "community.example/catalog",
    "id": "opaque-track-reference"
  },
  "playback": {
    "mode": "receiver-plugin",
    "protocol": "music.share@1",
    "suggestedPluginId": "community.example"
  },
  "policy": {
    "visibility": "unlisted",
    "expiresAt": "2026-09-25T00:00:00Z"
  }
}
~~~

namespace 和资源引用用于定位能力，不是安装指令或可执行表达式。建议插件只按可信安装来源展示，不能自动下载安装分享者指定的脚本。

分享服务自行分配 shareId，并保存所有者、服务端访问策略、撤销状态和必要的上游 grant 引用。这些字段不由客户端提供一个字符串就直接取得权限。

白名单允许文本、有限结构的资源定位、受控图片引用和标准播放计划；禁止 JS、JSX、WASM、函数表达式、命令、任意请求脚本和可执行“解析配方”。签名只能证明来源，不能让含代码的分享载荷变得可执行。

封面可能带私人签名 URL，应经授权导出为独立分享资源或使用可公开的封面地址。客户端 connectionId、内网主机、文件路径、credentialRef、API Key 和完整用户配置不能默认进入公开描述。

### 17.5 使用接收者自己的插件播放

分享页面显示歌曲信息并提供“在澜音打开”。接收端 Host 查找能处理该资源命名空间/协议的已安装 Provider：

1. 找到可用提供者时，由接收者选择自己的连接并授权解析。
2. 无对应插件时，展示兼容插件的可信安装入口或原站链接。
3. 来源不同但允许匹配时，明确询问是否用接收者已选择的其他音源匹配。
4. 未授权、匹配失败或资源私有时保留信息页，不循环尝试其他插件。

不要求接收者拿到发送者的 JS 文件。寄生插件的分享由父兼容器投影成标准协议，接收者使用自己的兼容器和 Guest，不能将发送者的 LX 脚本随链接带过去执行。

### 17.6 网页播放：标准委托解析协议

需要网页免装插件播放时，音源作者可以在现有服务端增加窄化接口。建议定义三个独立动作：

| 动作 | 调用者 | 作用 |
| --- | --- | --- |
| share.issue | 已认证的发送者，通过 Host 凭据代理 | 为指定歌曲和策略签发分享 grant |
| share.resolve | 登记过的分享服务或满足条件的接收者 | 用 grant 取得短期播放租约 |
| share.revoke | 分享所有者或受委托的分享服务 | 撤销 grant |

grant 限定歌曲/资源集合、有效期、接收者要求、播放/并发预算和允许调用方。它不能枚举完整音乐库、解析任意歌曲或恢复主 API Key。

推荐将真正 grant 保存在分享服务受保护的存储中；公开链接只包含不可猜测的 shareId。观众先通过分享策略检查，再取得短期播放会话。音源端按 grant 的 scope 和状态再次验证，不能只依赖 Ceru 分享服务的判断。

解析结果使用有限 Schema 返回媒体信息、过期时间和刷新条件，不能返回下一段要执行的代码。媒体代理检查重定向、流分片、密钥、Range 和目标地址，沿用网络安全规则。

作者的解析服务执行的是作者自己部署的正常服务端程序，Ceru 只实现这个固定协议；不接收用户上传的插件作为运行程序。

### 17.7 分享解析端点的登记与网络安全

不能把分享描述里的任意 URL 交给服务器 fetch。委托服务使用经过登记和验证的 resolverId，其服务端记录包含协议版本、发布者绑定、明确 HTTPS origin、允许路径和认证方式。

- 登记验证服务控制权与发布者关系，但仍将响应当不可信数据。
- 服务端拒绝回环、私网、云元数据、任意协议及未批准的重定向目标，并在真实连接时防 DNS 重绑定。
- 客户端不能提供任意请求头、主 Cookie 或用于拼接目标的任意表达式。
- 按 resolver、分享、观众和资源设置配额、超时、熔断与响应大小限制。
- 封面抓取、媒体代理同样不得成为任意 URL 转发器。
- 解析器版本不兼容或不可用时降级为信息页，不下载脚本修复兼容性。

私有 Navidrome 默认使用接收端已有访问权或服务端正式提供的分享功能；不把服务器密码或内网穿透能力自动交给公共分享服务器。是否公开元数据也由用户选择。

### 17.8 付费音源、隐私与撤销

动态生成的插件文件可能包含个人激活信息，**歌曲分享绝不直接上传这个文件或读取其中的卡密作为分享凭据**。

上游可以选择：

- 接收者必须使用自己的账号或卡密。
- 发送者拥有有限的访客分享额度，上游签发独立 grant。
- 只能分享歌曲信息和原站地址，不支持公开播放。

这些条件由上游验证。Host 展示将使用谁的额度、是否允许陌生访客、有效期和限制，不能把“发送者可播放”推导成“所有接收者可永久播放”。

链接支持仅持链接访问、指定接收者、密码等访问策略；不公开链接地址不等于严格私密。密码校验、速率限制和会话管理由分享服务负责。公开页面只记录必要的播放统计，不暴露购买记录或凭据。

撤销后分享服务立即停止创建新播放租约，并请求上游失效 grant。已经签发的短期媒体地址可能持续到自身到期，应限制 TTL 并如实说明；不承诺收回接收者已经获取的数据。

### 17.9 旧分享的迁移

新发布接口只接受数据协议，关闭上传与运行新 JS 的能力。已有链接可保留已保存的安全元数据；需要重新获得播放能力时，由所有者使用新插件能力重新签发，并尽可能沿用分享 ID。

无法迁移的旧链接显示“歌曲信息可查看，播放需要重新分享”或原站入口。不能为了维持旧链接，在无期限的兼容模式中继续执行上传脚本。

首版交付“信息分享 + 接收端插件播放”；随后为有需求的音源作者提供委托分享接口规范和示例服务。这样不需要先建设任意代码运行平台，就能提供可扩展的歌曲分享。

## 18. 当前只实现 Electron，保留未来适配边界

### 18.1 当前实现范围

本方案的插件安装、权限、生命周期、后台运行、界面渲染、LX 寄生管理和代码缓存，均面向当前 Electron 桌面软件。其他 App、iOS、Android、PWA 或浏览器版插件运行环境不属于本次开发和验收范围。

| 当前职责 | Electron 实现方向 |
| --- | --- |
| 可信 Host | 主进程侧管理安装身份、权限、生命周期、任务和系统能力代理 |
| 不可信逻辑 | 独立受限 runner，通过验证身份的 RPC 访问 Host；不能在主进程直接执行插件 |
| Schema Surface | 可信 renderer 解释有限 Schema，交互通过受控动作协议进入逻辑模块 |
| 高级 Web Surface | 独立且开启安全配置的 webContents，隔离来源、存储、导航与 IPC |
| 网络与媒体 | Host Broker 校验 origin、连接、凭据和媒体租约 |
| 系统资源 | 桌面系统密钥保管、选择器句柄、通知与媒体控制的内部适配器 |
| 单文件加载 | 校验收到的 JS，静态提取入口与资源，按需编译和启动对应隔离实例 |
| 断网/休眠/重启 | 由 Host 恢复任务与连接状态，重新检查授权和媒体有效期 |

普通子进程不是自动成立的 OS 沙箱；Electron 容器也不能仅凭一个安全选项就省略 IPC 鉴权。当前支持的桌面系统需要分别验证执行隔离与系统能力适配。

### 18.2 为后续客户端保留的少量边界

现在只约束以下设计点，不为未来平台提前编写实现：

- 公共 SDK 使用音乐资源、任务、权限、UI 数据等稳定协议，不暴露 Electron、Node 对象或内部 IPC 通道。
- 文件、凭据、通知和媒体后端经内部 PlatformAdapter 实现；插件持有句柄，不依赖桌面绝对路径。
- 可见模块优先使用 UI Schema；自定义界面通过有限消息协议通信，避免依赖可信 renderer 的组件实例。
- 能力由版本和 capabilities 查询表达；缺少能力能明确降级，不只根据平台名字猜测。
- 操作支持异步、取消和恢复，避免把业务依赖绑到窗口存活或永久内存状态。
- 单 JS 文件把核心代码、配置、资源和模块边界分清，未来可由新的加载适配器复用。

未来适配其他客户端时，可以重新实现运行器、系统代理和界面容器，同时尽量保持这些协议。这里的目标是降低移植成本，不承诺所有桌面插件在未来客户端无需调整。

### 18.3 分享网页的范围

第 17 节的歌曲分享网页属于当前分享功能：展示数据、控制标准媒体播放、跳转原站或唤起澜音。它不是浏览器版插件 Host，不加载发送者的插件文件，也不承担完整插件兼容。

当前里程碑不包含移动端运行器、应用商店分发、移动端后台调度或全端一致性测试。后续需要时再单独设计，不阻塞 Electron v2 的交付。

## 19. 四个端到端参考插件

### 19.1 纯后台音源插件

安装包只包含逻辑、图标、描述和协议声明，没有自定义 Surface。

1. Host 显示将新增的搜索/播放来源。
2. 用户首次选择来源，授权确切请求域名。
3. Host 根据元数据生成来源选项与图标。
4. 搜索返回通用资源，Host 用默认列表显示。
5. 播放解析返回媒体租约；429 返回结构化故障。
6. 停用后来源选项和注册撤回，其他插件继续运行。

若插件只有 resolve 能力，第 3 步只进入播放来源管理，不进入搜索选择器。

### 19.2 Navidrome 混合插件

一个包包含后台协议实现、Host 凭据表单和音乐库页面。

1. 用户点击“连接 Navidrome”。
2. 输入服务器，Host 解析实际 origin、端口与路径。
3. 对需要的网络范围授权；若为私网，再申请具体服务器访问。
4. 通过可信凭据表单创建 Connection 和 credentialRef。
5. 后台模块完成协议协商，报告连接能力与状态。
6. 搜索框增加“家庭服务器”，侧栏增加相应库入口。
7. 插件提供分类、歌单、收藏与榜单数据；使用 Schema 或高级页面展示。
8. 添加第二个服务器时创建第二个 Connection，凭据、缓存、限流和授权分开。
9. 关闭音乐库页面不停止正在播放的后台能力。
10. 退出某个连接撤销该连接访问，不影响另一个服务器。

这里不规定 Navidrome 某个版本的具体认证参数；实现时由连接协议适配层处理，避免让 Host 通用音乐 API 绑定到某个服务端细节。

### 19.3 歌单导入插件

包内包含链接识别、导入流程、一个按钮和可选平台连接表单。

1. 用户点击插件注入的“从平台导入”。
2. 输入链接；先本地识别，再申请目标访问。
3. 返回导入计划，Host 展示曲目数量、目标与重复处理。
4. 用户批准后获得特定歌单的写入租约。
5. Host 展示进度，插件按批提交并保存恢复游标。
6. 用户取消或权限撤销后停止新批次，展示已完成部分。
7. 重试使用幂等记录，不重复导入。

插件不需要拥有全库删除权，也不需要获得磁盘任意文件访问权。

### 19.4 LX 寄生插件兼容器

1. 用户安装“LX 兼容器”澜音插件，设置页出现其管理页面。
2. 用户在该页导入 LX 脚本，Host 展示父子身份与权限计划。
3. 用户批准子脚本的固定内容版本，Host 为它创建独立 Guest Runner。
4. 兼容器发布搜索 Provider、来源与音质 UI，并绑定可用 Guest。
5. 用户搜索时由兼容器的目录能力返回结果；播放时交给选定 Guest 解析。
6. Guest 首次访问新站点时，以它自己的身份申请权限。
7. Guest 的 429、更新提示和崩溃显示在兼容器页，并能追溯到具体子脚本。
8. 禁用一个 Guest 只影响对应解析能力；禁用兼容器则停用整棵父子树。

## 20. 开发者体验与可观测性

### 20.1 拟议 SDK

按领域组织少量稳定入口：

| SDK 区域 | 用途 |
| --- | --- |
| ctx.providers | 绑定已声明的音乐协议实现 |
| ctx.actions | 实现已声明动作，验证输入并返回结果 |
| ctx.services | 发布/消费版本化服务 |
| ctx.events | 订阅受权限控制的事件 |
| ctx.ui | 更新页面状态、请求通知与对话框 |
| ctx.config | 读取经验证的基础/个性化配置，敏感字段只返回引用 |
| ctx.permissions | 查询、申请和观察自身权限 |
| ctx.http | 受控网络请求 |
| ctx.credentials | 捕获、代用和管理自有凭据 |
| ctx.media | 创建/释放媒体租约 |
| ctx.share | 分享计划、预览、发布、接收端解析与撤销 |
| ctx.playback | 构造失败结果及限定的播放交互 |
| ctx.library | 按资源范围读取、写入和提交计划 |
| ctx.jobs | 可取消、可恢复的后台任务 |
| ctx.guests | 子插件安装、隔离运行、能力投影与父子生命周期 |
| ctx.storage | 有配额的私有存储 |
| ctx.effects | 注册需要随作用域回收的资源 |
| ctx.log | 脱敏、限流的诊断日志 |

这些入口是代理和协议，不是可直接操作 Host 内部对象的引用。跨隔离边界的调用使用 Promise；本地纯数据构造器可以同步。

SDK 必须同时生成类型、运行时校验、文档与测试样例。不能只有 TS 类型而没有接收端校验。

### 20.2 npm CLI 与脚手架

拟议提供 create-ceru-plugin 脚手架、@ceru/plugin-sdk 和 @ceru/plugin-cli，CLI 的本地可执行名为 ceru-plugin。以下是计划中的命令，不表示 npm 上已发布：

~~~text
npm create ceru-plugin@latest my-plugin
cd my-plugin
npm install
npm run dev
npm run build
npx ceru-plugin validate dist/my-plugin.js
npx ceru-plugin sign dist/my-plugin.js
npx ceru-plugin publish dist/my-plugin.js
~~~

需要动态售卖/发放时，可增加以下拟议命令及服务端库：

~~~text
npx ceru-plugin template dist/my-plugin.js --out dist/source-template.js
npx ceru-plugin issue dist/source-template.js --config delivery.json --out dist/customer-source.js
~~~

模板、delivery.json 和密钥配置属于开发/发行端输入；最终只把 customer-source.js 交给用户。高并发服务通过拟议的 @ceru/plugin-issuer 库复用模板和发放流程，CLI issue 主要用于本地生成、调试和批处理。

脚手架提供纯音源、连接型音乐库、歌单导入、LX 兼容器等模板；交互选择源语言和 UI 方式，输出格式始终为单个 .js。构建流程统一完成类型/协议检查、各入口打包、资源内嵌、静态头生成、单文件验证与可选签名。

这里“打包”指构建器合并代码和资源，不生成 ZIP。开发者可以使用 npm 发布 CLI；终端用户安装生成的插件文件不需要 Node/npm。

开发服务器支持本地热重载、权限模拟、平台能力模拟、429/断网/超时模拟，以及注册项预览。开发模式仍走相同 RPC 和权限路径，不能用绕过安全边界的调试方式掩盖发行版问题。

本地热重载明确显示未签名状态，避免复用正式发行身份；发布前生成带内嵌签名的 JS 文件，并验证与测试过的产物一致。

### 20.3 用户与开发者共用的诊断

插件详情应显示：

- 当前启用状态、连接、贡献项与缺失依赖。
- 已授权范围、最后使用时间、可立即撤销的控制项。
- CPU/内存、排队请求、失败率、最近一次崩溃和熔断原因。
- 安装来源、发布者、当前版本、包摘要、更新与撤销状态。
- 已脱敏日志及按操作串联的调用轨迹。

面向用户的错误应可行动，例如“缺少对家庭服务器的访问许可”“某依赖未安装”，而不是只有“插件加载失败”。审计记录存储在 Host，插件不能删除不利于自己的记录。

性能指标至少观察：冷启动、首次搜索结果时间、滚动流畅度、插件停用清理时间、崩溃恢复时间和空闲资源占用。数值目标经原型测试后确定，避免在设计阶段承诺未经验证的数据。

## 21. 分期实现与开发交付物

### P0：协议与隔离原型

交付：

- 身份/连接/资源模型、Manifest Schema、RPC Schema 与权限目录。
- 独立 runner 原型，完成无限循环、越权、撤权、崩溃回收验证。
- 宿主贡献注册表、生命周期事务和依赖诊断。
- 通用 Guest 身份、父子委托与单子项/父子树资源预算原型。
- 可信凭据输入、网络代理、媒体租约原型。
- 单 JS 格式、静态元数据提取、普通/分层签名规范与分享数据协议。

完成标准：一个故意崩溃或恶意访问的插件不能影响其他插件正常使用，也不能突破已声明和已授权范围。桌面 OS 隔离方式需要有实测结论。

### P1：可日用的 v2 核心闭环

交付：

- 单 JS 安装预览、启停、卸载、权限中心和受控更新。
- 搜索/播放/目录/导入协议。
- 搜索来源注入、侧栏项、分类与默认 Schema 页面。
- Navidrome 式多连接表单、凭据存储和媒体播放。
- 429/认证过期故障决策、导入计划与可取消任务。
- LX 兼容器、设置管理页、首批兼容 API 与子插件单独授权。
- npm 脚手架、单文件构建与最小动态发放工具。
- 信息分享和接收端插件播放，歌曲分享不上传或执行 JS。
- 四个参考插件及协议契约测试。

完成标准：不新增 Host 平台枚举即可安装新搜索来源；用户拒绝可选权限仍可使用其他能力；来源错误可恢复；所有安全必需检查已经具备。

### P2：高级自定义与组合

交付：

- 隔离 Web Surface、用户选择的页面/渲染角色。
- 自定义排行榜与歌单布局、复杂搜索过滤。
- 公开服务依赖、组合预设、可复用控件。
- 完整的更新回滚、性能诊断与开发模拟工具。
- Electron 动态发放的吞吐、内存与编译缓存验证。
- 有需要的音源作者接入标准委托分享服务，实现网页播放。

Web Surface 的隔离验收通过后才开放给普通用户；不能为了抢先提供自定义页面而暂时把第三方组件装入 Host 渲染树。

### P3：生态规模化

交付：

- 官方/第三方索引协议、发布者管理、审核与举报。
- 自动兼容性报告、撤销与供应链治理。
- 受控动作编排、布局预设分享。
- 桌面端发行服务、授权管理和分享服务的规模化运营。

依赖具体系统能力的扩展优先做成随宿主发布的窄接口适配器。第三方原生插件如未来确有必要，应另立安全与分发规范，不混入普通包通道。

### 旧系统的概念迁移原则

不要求一次性重写所有业务：

1. 先定义目标协议，把官方现有能力视作协议适配器。
2. 新插件优先使用 v2；旧插件通过受限兼容层运行，并清楚标记能力缺口。
3. 旧平台代码可留在各自适配器内部，不能继续扩散到通用资源模型和 UI。
4. 兼容层不能为了兼容旧 API 而暴露任意 IPC 或默认全权限。
5. 原有用户数据保留稳定引用或迁移映射，记录无法映射的资源，避免静默丢失。

这是迁移策略，不涉及当前仓库的文件改动方案。

| A11 | 合法域名重定向到未授权域名/私网 | 新连接被拒绝，凭据不转发 |
| A12 | DNS 重绑定、IPv6 或特殊 IP 写法 | 按最终网络目标验证，不能绕过私网限制 |
| A13 | 媒体分片、封面 URL 请求未授权目标 | 与普通网络请求一样受限 |
| A14 | Web Surface 访问 Host DOM 或任意 IPC | 无法访问，插件仍受隔离 |
| A15 | 无限循环、内存暴涨或事件轰炸 | 当前插件被中断，其他界面可操作 |
| A16 | 429 且允许先提示 | 自动换源在同一决策中暂停，出现有归属的恢复交互 |
| A17 | 429 但用户要求始终自动换源 | 插件不能阻塞策略，当前服务仍遵守冷却 |
| A18 | 插件等待时用户停止/禁用/撤权 | 立即取消等待与后续重试 |
| A19 | 交互无人处理或界面销毁 | 截止后释放等待，保留明确状态，不隐式授权 |
| A20 | 卡密过期 | 显示第三方插件来源，不伪装成 Ceru 官方要求 |
| A21 | 两个来源互相失败 | 不无限循环，遵守候选数和总时间预算 |
| A22 | 导入预览后插件改变目标或操作类型 | 旧批准失效，需要新计划 |
| A23 | 导入中断后继续 | 不重复插入，展示已完成部分 |
| A24 | 插件通过依赖代理访问被拒绝资源 | 调用链检查阻止越权 |
| A25 | 缺失依赖或循环依赖 | 展示原因，不能永久无提示等待 |
| A26 | JS 被篡改、包含额外执行语句或超量内嵌资源 | 执行任何代码前拒绝安装 |
| A27 | 同 ID 不同发布者覆盖安装 | 不继承旧身份或权限 |
| A28 | 更新扩大权限或更换目标域 | 未同意前新范围不可使用 |
| A29 | 新版迁移失败后回滚 | 数据可恢复，撤权和凭据删除不被逆转 |
| A30 | 热重载后旧实例迟到回调 | 不重新注册条目、不覆盖新状态 |
| A31 | 分享网页无法取得播放授权 | 降级为信息/原站入口，不上传 JS 或转发个人主凭据 |
| A32 | Electron 重启、休眠或任务中断 | 按幂等步骤恢复，重新检查权限 |
| A33 | 卸载提供歌单来源的插件 | 用户已保存歌单保留，来源缺失状态可解释 |
| A34 | 所有业务插件关闭 | 插件管理、权限中心和恢复默认预设仍可访问 |
| A35 | 不安装 LX 兼容器 | Host 无 LX 专用页面，不识别或执行 LX 格式 |
| A36 | 安装兼容器后导入 LX 脚本 | 设置页完成子插件管理，搜索与播放通过标准协议接入 |
| A37 | 子脚本只有解析能力 | 搜索由父插件或明确依赖提供，不虚构子脚本能力 |
| A38 | 子脚本尝试使用父插件/兄弟凭据 | 身份和作用域校验拒绝，父子授权不继承 |
| A39 | 子脚本首次访问动态域名 | 使用 Guest 身份授权；无用户意图时不后台刷弹窗 |
| A40 | 关闭一个 Guest | 兄弟 Guest 与兼容器搜索继续工作 |
| A41 | 禁用或卸载父兼容器 | 子项不能继续运行，投影撤回，归档可恢复 |
| A42 | 未签名脚本同名更新但内容改变 | 根据新摘要重新批准，不以自报版本继承信任 |
| A43 | 子项大量创建/连续崩溃 | 父子树总预算与熔断生效，不放大宿主资源 |
| A44 | 更换 LX 解析脚本 | 搜索目录资源引用稳定，已有歌单不会因此丢失 |
| A45 | 兼容层或子脚本请求不支持 API | 明确错误，不通过放宽隔离获得兼容 |
| A46 | 开发者使用 JSX/TSX 和多个资源文件 | 构建后用户只需安装一个标准 .js 文件 |
| A47 | 静态头含 getter、重复字段或执行表达式 | 安装器不执行代码，拒绝非法结构 |
| A48 | 同模板发放大量不同名称和激活信息 | 不逐用户构建/全文替换，固定载荷复用，用户配置不串用 |
| A49 | 个性化名称含引号、换行或注释终止符 | 按数据安全编码，不改变 JS 语法或产生新执行语句 |
| A50 | 个性化数据试图扩大权限或改入口 | 模板规则和发放签名校验拒绝 |
| A51 | 篡改核心、冒用模板摘要或混合另一份发放证明 | 在执行前拒绝，不能降级绕过签名 |
| A52 | 已有核心缓存，但换了个人配置 | 验证本次交付，复用代码缓存，不复用授权或实例堆 |
| A53 | 文件被复制、激活码重放或订单撤销 | 授权服务按账号/设备/期限规则处理，签名不替代权益验证 |
| A54 | 个性化下载经共享缓存或诊断日志 | 不能将个人激活信息发给其他用户或写入普通日志 |
| A55 | 分享歌曲时插件返回完整配置或代码 | Host 白名单拒绝，不上传用户 JS、卡密或主 API Key |
| A56 | 接收者没有同一音源插件 | 提供明确安装/原站/信息入口，不自动下载执行脚本 |
| A57 | 分享描述指定私网 URL 或任意脚本解析器 | 分享服务拒绝，只接受登记过的固定协议 |
| A58 | 分享 grant 越权、到期、撤销或额度不足 | 上游和分享服务共同拒绝新播放租约 |
| A59 | 分享链接要求使用发送者付费额度 | 发布前明确说明，依赖独立 grant，不能转交主凭据 |
| A60 | 分享模式不支持网页播放或旧分享无法迁移 | 显示可用降级路径，不恢复服务器运行用户插件 |

安全验收不能只由“正常示例插件能跑”代替。上述越权、竞态、恶意输入与故障测试应是 SDK/Host 契约测试的一部分。

## 23. 开发前需固定的决策

以下建议可直接作为第一轮架构决策记录：

| 决策 | 默认选择 | 重新评估条件 |
| --- | --- | --- |
| UI 优先级 | Schema 为基础，高级 Web Surface 后续开放 | 常见页面无法表达且替代方案已验证隔离 |
| 不可信逻辑引擎 | 优先验证 QuickJS 受限 runner | 性能、兼容性或端支持实测不满足 |
| 桌面隔离粒度 | 每插件实例独立进程和运行时 | 有数据证明资源压力过高且替代隔离成立 |
| 多账号隔离 | 同包下多个 Connection，授权与资源独立 | 某类敏感连接需要进一步拆分运行单元 |
| 业务互操作 | 标准音乐协议 + 命名空间扩展 | 出现多个插件共同需要的新协议 |
| 默认角色覆盖 | 用户明确选择，始终可恢复 | 不允许由插件自行放宽 |
| 429 阻止换源 | 当前操作、有权限、限时等待 | 用户策略优先调整 |
| 凭据 | Host 保管并向指定目标代用 | 特殊协议必须申请单独的明文读取例外 |
| 权限同步 | 不跨设备自动复制 | 未来有明确设备信任与再确认方案 |
| 分发 | 一个内嵌校验信息的 .js 文件 + 静态更新描述 | 新渠道仍必须满足同等校验 |
| JSX/TSX | 开发期输入，构建时转换为 JS | 发行和分享格式保持单个 .js |
| 普通插件原生代码 | 不支持 | 单独完成新的安全与发行规范 |
| LX 格式支持 | 由澜音原生兼容器插件实现 | 不向 Host 通用层回灌格式专用逻辑 |
| 寄生执行 | Host 单独登记身份与隔离，父插件提供兼容环境 | 不允许变成父权限下的任意脚本执行 |
| 寄生层数 | 第一版一层，独立授权与父子树预算 | 更深层需求另行验证安全与体验 |
| 当前实现端 | Electron 桌面端与必要的歌曲分享网页 | 其他客户端后续单独设计，仅预留稳定适配接口 |
| 个性化发行 | 预构建模板 + 小型配置 + 分层签名 | 代码/权限上限改变时才重新发布模板 |
| 歌曲分享后端 | 保存数据，调用已登记的分享协议 | 不开放上传用户 JS 的执行通道 |

第一轮需要产出的核心工程规格是：**单 JS 格式与构建规范、Manifest Schema、权限范围规则、音乐协议、UI Schema、RPC、故障决策状态机、Guest 托管协议、模板与发放签名、歌曲分享协议，以及相应契约测试。**当前围绕 Electron 实现这些边界，后续增加音源、页面或玩法时主要通过插件完成。

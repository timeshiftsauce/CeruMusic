# 澜音 v3 插件开发文档编写方案

## 适用范围与待确认项

这套中文文档以 CLI / SDK 3.0.0、Node.js 22.12.0 及以上、支持 v3 的澜音桌面 2.5.0 测试构建为教学基线。新手优先，其次是已有 v2 插件的维护者和需要查询契约的作者。首条路线使用 npm、TypeScript 和 Vue；普通 DOM、JavaScript 和已有 Web 项目另设入口。桌面版本号、清单版本和开发包版本分别标注。

1. **新手第一次必须看到什么？** 建议以侧栏出现「音源搜索」、改一句文案后看到重载作为十分钟练习的终点。首次下载 Node、npm 依赖或获取桌面测试构建的时间单独记录。带存储的计数器放到第二课。
2. **公开站的读者从哪里获取支持 v3 的桌面？** 稳定版发布前，建议写明测试构建要求，提供纯 CLI 验证路线；如有你认可的公开测试版下载页，再补链接。发布软件另外由你决定。
3. **插图如何分工？** 建议对安装入口、CLI 输出和运行结果使用去掉个人路径的实测截图；对权限、播放和数据流使用带文字替代的流程图。你提供的图像模型可用于概念插画，本次环境尚未确认该服务的专用凭据。教程的命令、按钮、权限和错误消息均从实测或源码取得。

## 风险与审校办法

- SDK 声明反映作者能编写的代码，桌面的实际支持还要核对对应版本的处理逻辑。参考条目标出适用版本、权限键、输入输出、异常条件和最小调用；只有资料明确时才填写默认值和错误码。
- 模拟服务、Hook 场景、静态校验、桌面实测分开记录。两个模拟用例都通过不能证明扫码、跨插件真实启停或音频硬件行为。
- 模板生成的代码和教程容易漂移。固定 CLI/SDK 基准，在干净目录重新生成工程，从教程实际代码构建并校验。截图去除个人路径、账号、二维码票据和凭据。
- 对照 v2 功能目录与 v3 SDK 导出清单逐项标注“保留、变化、兼容或待确认”，尤其复核签名、SDK 类型和插件运行时的界限。版本升级时重新审校。
- 最终交付审校报告，列出术语、命令、签名、交叉链接、权限、版本、各示例的执行结果和待确认项。没有目标系统验证过的结果不填“通过”。

## 执行与交付

编写方案经确认后，按读者任务连续完成各章，最终统一审校。版本、示例、权限与导航的验证结果和待确认项见[全书一致性审校记录](./plugin-v3-editorial-review.md)。

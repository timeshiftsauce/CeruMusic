# 按现象排查插件问题

> 适合已经生成工程或收到插件报错的作者，约 6 分钟。保留复现用的工程、CLI 版本和桌面版本。先用下表找到最后一个成功步骤，再去对应章节查参数。

| 现象 | 最小检查 | 修复后怎样验证 |
| --- | --- | --- |
| 终端报告找不到 npm 或工程 | 运行 `node --version`、`npm --version`，确认当前目录有生成的 `package.json` | 执行 `npm run` 能列出工程脚本 |
| 开发者模式已开启，却找不到成品 | 等 `npm run dev` 打印 `CERU_BUILD_READY`，从该行复制完整路径 | 预览列表出现对应文件与 v3 标记 |
| 已加载但没有侧栏入口 | 从 `ui.pages` 查 mount、view、when，再查 `entry.views` 和顶层 `entries` | 用相同宿主与账号打开页面，并切换来源验证显隐 |
| 点击没有反应 | 把视图调用的动作名与清单和 Logic 注册的 ID 逐字比对，捕获 Promise 错误 | 点击后观察日志，再检查视图状态用的是 view ID |
| 搜索正常，点歌失败 | 检查是否单独允许播放、引用是否完整、解析器能否返回该曲目的可播地址 | 用同一首已知可播曲目重试，再测缺失地址的歌曲 |
| 扫码完成，读资料却提示未授权来源 | 核对账号绑定与目标请求的 HTTPS origin、端口和凭据使用授权 | 重登后验证资料，再切换账号核对收藏归属 |
| 离线 Hook 用例通过，桌面没触发 | 核对宿主版本、用户实际操作入口、授权，以及管理设置中的暂停状态 | 同一输入分别试授权和撤权，记录预期与实际 |
| 更新后数据看起来消失 | 检查清单 ID、开发预览或普通安装、键名与数据版本 | 在备份副本复测旧版写入、同 ID 更新和新版本读取 |

## 把一次失败缩小到能复现

1. 在独立测试配置加载官方未改模板，先证明宿主能打开对应页面。
2. 只加入触发问题的改动。记录按钮名称、操作顺序、最后一条成功日志、第一条错误和对应动作 ID。
3. 报告中写明 CLI / SDK / 桌面版本、是否普通安装、是否开启严格模式与权限状态。遮盖私人路径、账号、二维码票据和请求头。
4. 修好后重跑原步骤，再测一次取消或拒绝路径。若涉及升级，使用已备份的数据复测。[首次预览](./quick-start) · [安装与升级](./publishing) · [v2 迁移](./migration)

## 例：侧栏有搜索框，点击歌曲却不能播放

先在宿主自己的曲库里播放同一首测试歌。如果这里也失败，检查文件或音源解析。若宿主可以播，回到插件搜索一次，确认这条结果来自预期音源。然后只检查播放这一步：页面用了哪个动作 ID，Logic 是否能用本轮条目 key 找回原始引用，当前用户是否允许清单里的 `listen` 权限。

每次只改变一个条件。允许播放后用刚才的歌曲重试，再撤销该权限，确认搜索仍能得到结果。若换另一个关键词后才出错，重新点击新列表中的结果，检查上一轮异步请求有没有覆盖本轮状态。[搜索、播放与结果归属](./music)

## 例：扫码成功，资料页仍然打不开

把二维码轮询和后续资料请求分开看。先核对账号状态有没有完成，再对照第一条失败的资料请求，逐项比较它的协议、主机和端口与该账号允许使用凭据的来源。同一平台的两个子域可以有不同的来源。修正声明或授权后，从用户登录入口重新建立连接，分别打开资料页和收藏页。记录结果时保留来源和错误消息，删去带票据的查询参数、Cookie 及二维码。[账号登录流程](./accounts)

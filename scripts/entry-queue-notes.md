# 应用入口队列

- 主进程在 `router/pendingLinks.ts` 按接收顺序编号，歌曲分享、歌单分享、一起听、插件文件和插件链接共用一份待处理列表。正在排队的同类型同内容请求去重。
- 主进程发出的 `deeplink:changed` 只是通知；渲染层重新读取完整有序列表，避免冷启动拉取与实时通知交错导致乱序。处理结束后才通过 `deeplink:ack` 移除，刷新页面前未确认的请求仍可重新读取。
- `services/entryQueue.ts` 是无框架依赖的 FIFO。同一时间只有一个异步任务运行；任务失败会记录错误并继续后面的任务。
- App 初次进入 `/home/*` 后开放队列，之后在首页子页面或设置页都能处理。在欢迎页、桌面歌词等独立页面不会执行。OAuth 回调直接处理，不排队，否则等待登录的任务可能产生死锁。
- 一起听任务直到用户取消、登录操作结束或加入完成才结束。插件安装直到确认、安装成功/失败才结束。歌曲分享等待加入播放列表并播放；歌单分享等待导航完成。
- 剪贴板一起听邀请、插件更新通知也使用该 FIFO，避免入口弹窗相互覆盖。普通权限对话框仍是所执行任务内部的授权流程。
- 打开外部 `.js` 文件仅预览静态元信息，用户确认后安装；不自动使用。非澜音格式只提供正在运行的兼容插件声明的格式，不在软件里硬编码 LX。
- Windows/Linux 参数按原顺序遍历；开发模式跳过 Electron 的应用入口参数。macOS 窗口尚未创建时的支持链接和插件文件先存入队列。不接管系统所有 `.js` 文件的默认关联，可通过“打开方式：澜音”传入。

验证：`node scripts/check-entry-queue.mjs`；`node scripts/check-plugin-lifecycle.mjs scripts/external-plugin-smoke.cjs`。

歌单文件 `.cmpl/.cpl` 的既有文件导入流程保持独立；本轮统一的是上述外部链接和插件文件入口。
